# QYNO 0.26.13

QYNO **0.26.13** 用の VS Code 拡張です。配布ファイルは同じフォルダの
[`0.26.13_VSCode_option.vsix`](0.26.13_VSCode_option.vsix) です。
VS Code 1.85 以降に対応します。

int / unsigned intは32bitの別名です。int_8 / int_16 / int_32 / int_64とunsigned整数型の
ハイライト・宣言解析・補完・引数ヒントに対応します。lengthとfile.writeの戻り値はint_64、
型を省略したforカウンターはautoと表示します。

complex / complex_64 / complex_128と虚数リテラル、型付き変数・配列要素のreal / imag補完、
成分のホバー、名前付き構築の補完・引数ヒントに対応します。

## インストール

VS Code の拡張機能画面右上の「…」から **VSIX からのインストール…** を選び、
`0.26.13_VSCode_option.vsix` を指定してください。CLI でもインストールできます。

```sh
code --install-extension vscode-extensions/0.26.13_VSCode_option.vsix --force
```

`.qy` ファイルを開くと有効になります。別の拡張が `.qy` を担当している場合は、
画面右下の言語モードを「QYNO」に変更してください。手動の補完表示は Ctrl+Space です。
Marketplace への公開やコンパイラのインストールは行いません。
拡張機能の表示名は **QYNO 0.26.13** です。同じバージョンをインストール済みの場合も、上のコマンドで更新できます。

## 機能

- auto / const auto のハイライト、変数名補完と定義参照。型表示は宣言どおり auto とし、この段階では推論結果に基づくメンバー補完は行いません。
- 型名を省略した `name = value` のローカル宣言と、既存変数への代入を区別します。内側の明示的な同名宣言と、ブロック終了後の外側の名前への参照に対応します。
- ファイル先頭・ローカルの `const NAME = value` / `const auto NAME = value` を認識し、前方参照・モジュール経由の補完・定義参照と、定数のホバー・アウトラインに対応します。型表示は `const auto NAME` です。
- `auto f(int x)` / `f(int x)` の関数・メソッドを認識し、補完・定義参照・引数ヒント・ホバー・アウトラインに対応します。戻り値は auto と表示し、通常の呼び出し文を関数宣言として扱いません。
- `f(x)` / `f(auto x)` / `f(ref x)` の省略した引数を auto と表示し、引数名補完・定義参照・ホバー・引数ヒント・ref付き呼び出しの補完に対応します。

- init の名前付き引数を、宣言・代入・戻り値・関数引数・入れ子・配列・add の文脈で補完。
- 必須引数と既定値の表示、引数名の定義参照・ホバー、生成用の引数ヒント。
- init を通常のメソッド補完から除外し、アウトラインには生成処理として表示。

- const モデル・readonly メソッド・ref readonly 引数のハイライトと型表示。
- const / readonly の対象では readonly メソッドと読み取り候補を提示し、変更メソッド・配列の変更操作・addr を候補から除外。

- model の型名・フィールド・メソッド・this の補完と定義参照。
- public / private のハイライト、補完候補の公開範囲、ホバー・アウトラインへの公開指定表示。
  private は同じモデル内部の this・同型インスタンスで補完し、外部や別モデルでは候補から除外します。
- 型、関数名、変数名、数値、コメント、文字列、文字列内の `{式}` のハイライト。
- `{式}` の括弧・変数・関数・演算子を文字列の色から分離し、通常のコードと同じテーマの色で表示。
- 文字列やコメントの外でセミコロンを記述して Enter を押すと、タブ1段深くする。型名を省略した関数やユーザー定義型にも対応。
- `qyc` による構文・型・名前解決の診断。エラーは赤線と「問題」パネル、コンパイラの警告は警告として表示。
- ユーザー定義関数・引数・変数・定数の補完。インデントと宣言位置を考慮し、別関数や終了したブロックのローカル名を候補から除外します。
- `import geometry.circle`、`using geometry.circle as circle`、選択的な `using` に対応した名前・メンバー補完。
- import 不要の `io`、`io.file`、`math`、型変換と従来の `print` / `input` の補完。
- 配列の `.length` / `.add()` / `.remove_at()` / `.clear()`、文字列の `.length` などの補完。
- 関数呼び出しの引数ヒントと `ref` を含む呼び出しスニペット、ホバー説明、定義への移動、アウトライン。
- 関数・ループ・分岐・明示的な close を含むファイル操作のスニペット。

編集中の未保存のソースも補完に反映します。コメントや文字列の通常の本文では候補を出さず、
文字列内の `{式}` ではコードの候補を表示します。
QYNO のインデントに合わせてタブ、幅4を既定にします。個人の設定で変更できます。

```text
using io.file as fs

void increase_all(ref int matrix[][]);
	for(0 <= i < matrix.length, i++);
		for(0 <= j < matrix[i].length, j++);
			matrix[i][j]++

int main();
	int matrix[2][3]
	increase_all(ref matrix)
	io.print(matrix)
	return 0
```

`increase_all`、`matrix`、ループ内の `i` / `j`、`fs.open` などを補完できます。
関数の配列引数は **`ref int matrix[][]`**、呼び出しは **`ref matrix`** です。

## モジュールの探索設定

既定の探索起点は編集中のファイルのディレクトリです。
エントリ以外のファイルも編集するプロジェクトでは、ワークスペースの `.vscode/settings.json` に
エントリファイルと `qyc -I` に相当する探索ルートを指定してください。

```json
{
  "qyno.entryFile": "app/main.qy",
  "qyno.moduleRoots": ["modules", "../shared/modules"],
  "qyno.maxIndexedFiles": 2000
}
```

設定の相対パスはワークスペースフォルダが基準です。絶対パスも指定できます。
エントリのディレクトリ、追加ルートの順に `geometry/circle.qy` を探します。
`..` による上位階層のルート指定も可能です。
ワークスペースを開いていない場合、相対設定は編集中のファイルのディレクトリが基準です。

モジュールパス候補の探索は `qyno.maxIndexedFiles` 件の `.qy` を上限とし、
識別子として有効なディレクトリ・ファイル名を辿ります。シンボリックリンク、
`node_modules` や隠しディレクトリは辿りません。
ユーザーモジュールの関数・定数は、そのファイルに `import` したものを提示します。

## 検証と制約

診断には別途 **QYNO 0.26.13 の `qyc`** が必要です。PATH 上の `qyc` を既定で使用します。
Windows などで PATH にない場合は、設定の `Qyno: Compiler Path` に `qyc.exe` のフルパスを指定してください。

```json
{
  "qyno.compilerPath": "C:/QYNO/qyc.exe",
  "qyno.diagnostics.enabled": true,
  "qyno.diagnostics.delay": 500
}
```

信頼済みのワークスペースで、編集中の変更から既定500ms後に検査します。コマンドパレットの
**QYNO: Check Current File** でも即時に検査できます。診断を無効にする場合は
`qyno.diagnostics.enabled` を `false` にしてください。コンパイラがない場合は、その設定方法を警告表示します。
未信頼のワークスペースや仮想ファイルシステムでは、コンパイラを起動しません。

検査対象は `qyno.entryFile` を指定していればそのエントリと依存モジュール、未指定なら編集中のファイルです。
モジュールを編集する場合は `qyno.entryFile` と `qyno.moduleRoots` を設定してください。
新規の未保存ファイルと、ファイルの未保存変更・インポート先の未保存変更にも対応します。
新規ファイルの探索起点は、ワークスペースの先頭フォルダです。ワークスペースがない場合は一時ディレクトリになります。

ソースの一時コピーに対して `qyc -S` を実行し、生成したアセンブリも一時ディレクトリとともに削除します。
ソースを自動保存せず、プロジェクト内にビルド成果物を生成せず、ユーザープログラムを実行しません。
編集が進むと古い検査を中止し、終了時には一時ファイルを削除します。検査のタイムアウトは10秒です。

コンパイラは最初のエラーで停止するため、エラーを修正すると次のエラーを表示します。
未宣言の変数の読み取り・関数呼び出しはエラーですが、`name = value` による暗黙の変数宣言は従来どおり有効です。
型検査には close 漏れなどの既存の検査も含まれます。
補完は引き続き未完成のコードでも候補を提示する軽量な解析です。複雑な式の型推論やすべてのメンバー補完は行いません。

開発用のパッケージ作成には Node.js 22 以降が必要です。拡張自体に npm 実行時依存はありません。

```sh
cd vscode-extensions
npm ci
npm run check
npm test
npm run test:editor
npm run package
```

`test:editor` は VS Code 1.85.2 を取得して実際の拡張ホスト上で補完・定義・ホバー・引数ヒント・
アウトライン・未保存変更・Enter時のインデント・コンパイラ診断を検証します。
コンパイラ連携のテストには、リポジトリのルートで事前に `make` してください。
Linux の GUI のない環境では Xvfb などが必要です。
取得済みの VS Code を使う場合は `QYNO_VSCODE_EXECUTABLE` に実行ファイルのパスを設定できます。
`npm run package` はこのフォルダに VSIX を出力します。内部の拡張バージョンは SemVer の `0.26.13`、
配布ファイル名は `0.26.13_VSCode_option.vsix` です。

## インターフェース

interface / implements のハイライト、型名補完、契約メソッドの補完・定義参照・ホバー・引数ヒント・アウトラインに対応する。
`ref readonly` の対象では readonly の契約メソッドだけを候補にし、interface に addr / value は表示しない。
実装側だけにあるフィールドやメソッドは契約の補完に混ぜない。契約の型検査と特殊化はコンパイラが行う。

## ビット演算と整数基数

xor / bnot、<< / >>、0b / 0o / 0d / 0xと、整数書式のハイライトに対応する。
print / input / file.write内の式・変数・配列要素の補完と定義参照を維持し、コロンの後では4基数の書式だけを補完する。
int / strのbase / prefix引数をヒントへ表示し、名前付き引数の記述順が異なる場合も現在の引数を示す。
intのbaseは文字列の解析、strのbase / prefixはintの文字列化にだけ使用できる。
