# モデルのカスタム初期化

状態: QYNO 0.26.3 で実装済み。

モデル生成時に呼ばれる init を定義できる。
private の初期値設定、入力の検査、派生した値の計算を生成手順にまとめる。
型名を繰り返さない `{名前=値}`、値コピー、readonly、明示 close の規則を維持する。

## 1. 推奨記法

```text
model Rectangle;
	private double width
	private double height

	public bool init(double width, double height);
		if(not(width > 0.0 and height > 0.0));
			return false
		this.width = width
		this.height = height
		return true

	public readonly double area() = this.width * this.height

int main();
	Rectangle rect = {width=3.0, height=4.0}
	io.print(rect.area())  // 12.0

	Rectangle copy = rect // init を実行しない、独立したコピー
	io.print(copy.area()) // 12.0
	return 0
```

init のあるモデルの `{width=..., height=...}` は、init の引数を名前で指定する。
外部に公開するのは引数名であり、同名の private フィールドへの直接アクセスを許可するわけではない。
フィールドと引数の名前を一致させる義務はない。

init のない従来のモデルでは、引き続き public フィールドの名前付き初期化子として扱う。
モデルが init を定義したことを境界にし、生成時の入力を1つの入口へ集約する。

## 2. 宣言と引数

| 宣言 | 成功の意味 |
| --- | --- |
| `public void init(...);` | 本体の末尾に到達するか、`return` で完了 |
| `public bool init(...);` | `return true` で完了。`return false` は生成拒否 |

公開指定の省略は public。init はモデルごとに最大1つとし、オーバーロードは導入しない。
init の戻り値型は void / bool のみ。本体はブロック形式とし、数式形式は導入しない。
bool の全ての通常終了経路には bool の return が必要。

初期段階では public の init のみを許可し、private / readonly / const の指定は受け付けない。
private な生成入口と静的ファクトリの組み合わせは、静的メソッドを設計する段階で扱う。
モデルのフィールド・通常メソッドの名前 init は専用名にする。
init は文脈依存の専用名とし、トップレベルの通常関数・変数・モジュール名としての使用は維持する。
既存モデルの init フィールドや通常の init メソッドは、導入時に改名が必要。

init は生成専用であり、`rect.init(...)`・`this.init(...)`・モジュール経由で直接呼べない。
再生成したい場合は `rect = {width=5.0, height=6.0}` と書き、新しい値に置き換える。
通常メソッドや通常関数の名前付き引数は、この実装単位には含めない。

引数は型を明記した値引数とし、既存の型変換・モデルと配列の値コピー規則を使う。
配列の次元は従来どおり名前の後に書く。
ref / ref readonly / const 引数は導入しない。val の明示は既存の値引数と同じ意味で許可する。
file または file を再帰的に含む型は init の引数に受け付けない。第10節の所有権の境界を保つためである。

引数の既定値は init に限って導入する。

```text
model Point;
	private double px
	private double py

	public void init(double x=0.0, double y=0.0);
		this.px = x
		this.py = y

	public readonly double distance() = math.sqrt(this.px^2 + this.py^2)

int main();
	Point origin
	Point horizontal = {x=3.0}
	Point p = {y=4.0, x=3.0}
	io.print(origin.distance())     // 0.0
	io.print(horizontal.distance()) // 3.0
	io.print(p.distance())          // 5.0
	return 0
```

名前で指定するため、既定値のある引数と必須引数を並べる順序は制限しない。
省略した必須引数・未知の引数名・重複名・型や配列制約の不一致はコンパイルエラー。
同名の public フィールドが存在しても、未知の引数をフィールド指定に読み替えない。

## 3. 初期化子の意味を一貫させる

init の有無による選択は、型解決後に1回行う。
代入・関数の引数と戻り値・配列要素・add の引数・フィールドの既定値でも同じ規則を適用する。

```text
Rectangle rect = {width=3.0, height=4.0}
rect = {width=5.0, height=6.0}

Rectangle make_rectangle(double width, double height);
	return {width=width, height=height}
```

同じモデルのメソッド内部でも、init があれば `{...}` は init の引数になる。
private フィールドを直接指定して検証を省く生成記法は用意しない。
`raw {...}` や、失敗時に従来のフィールド初期化へ戻る仕組みも導入しない。

既存の `Point()` は引数を全て省略した生成として維持する。
init があればその既定値で呼び、必須引数があればコンパイルエラー。
`Point(3.0, 4.0)` や `Point(x=3.0, y=4.0)` は今回追加せず、型の文脈がある `{x=..., y=...}` を基本とする。
生成後の `rect.width = ...` は通常のメンバー更新であり、init を再実行しない。
既存の public / private と readonly の検査を適用する。

## 4. 生成と評価の順序

1. 生成先の型と init の引数を解決し、名前・必須引数・型・公開範囲を検査する。
2. 明示された引数式を、記述した順に左から1回ずつ評価する。値引数のスナップショットを作る。
3. 省略した引数の既定値を、引数の宣言順に1回ずつ生成する。
4. 生成用の領域を確保し、フィールドを宣言順に初期化する。初期化できないフィールドは第6節の未完了状態にする。
5. 暗黙の this と引数を渡して init の本体を1回実行する。
6. 成功した場合だけ、完成した値を宣言先・代入先・引数・戻り値へ渡す。

本体へ渡す順序は引数の宣言順だが、引数式の評価順序は書いた順を維持する。
モデル・配列の値引数は、後続の引数の副作用で内容が変わらないよう、各評価位置でコピーする。
指定されていない既定値だけを生成し、明示した引数に対して既定値を先に実行しない。

フィールドの初期化では、型のゼロ値・既存の既定値・入れ子の init を使う。
入れ子を通常生成する場合は、その init を完了させてから親の init 本体へ進む。
GC は生成途中の領域・引数・フィールドを保持し、ユーザーは未完了の領域を直接指定できない。

宣言中の変数名は、初期値式の評価が終わるまで利用できない。
代入では新しい値の生成を先に完了させ、最後に既存の場所を置き換える。
引数式・初期化処理の入出力や、別の変数への副作用を巻き戻す保証は追加しない。
`rect = {width=mutate(ref rect), ...}` のように引数式が既存値を変更した場合、その変更まで元には戻さない。

## 5. 既定値は生成用の式として保持する

フィールドと init 引数の既定値には、既存の定数式に加えて、定数の入力を持つモデル生成式を許可する。
通常関数・通常メソッドの呼び出し、input、直接の file.open は既定値式には書けない。
他の引数・ローカル変数・this を参照することもできない。
他の引数を使う計算や、ファイルの open は init の本体に書く。

init を持つモデルの `{...}` や `Type()` が既定値に含まれる場合は、必要になった生成ごとに init を実行する。
引数が定数だからといって、実行結果や副作用をコンパイル時にキャッシュしない。
init を持たないモデルの従来の定数値は、既存の最適化と独立した値コピーを維持する。

既定値の名前解決・public / private の検査は、既定値を書いた宣言元の字句スコープで行う。
外部の生成位置で再利用しても権限を変えず、初期化先の型の private 権限を付与しない。

フィールドの型だけでなく、引数の既定値を通じた無限の既定生成も検査する。
例えば `void init(A other={})` が再び同じ A の既定生成を要求し続ける場合や、
A / B の既定引数が互いの既定生成を要求する場合は、定義時に循環エラーとする。
既定生成の依存検査は保守的に行い、既定値式に書かれた生成の循環を許可しない。
通常の本体内で明示的に行う再帰は既存の関数再帰と同様に扱い、file の再帰解析の制限も維持する。

## 6. 必須引数を持つ型のフィールド

init に必須引数がある型は、引数なしでは生成できない。
その型をフィールドに持つ親は、フィールドの既定値で引数を与えるか、親の init 内で完成させる。

```text
model Panel;
	private Rectangle bounds

	public void init(double width, double height);
		this.bounds = {width=width, height=height}

	public readonly double area() = this.bounds.area()
```

Rectangle には必須引数があるため、この bounds は親の init 開始時には未完了。
ゼロ値を Rectangle の完成した値として扱ったり、必須引数の検査を省いて生成したりしない。
`this.bounds = {...}` の右辺の生成が成功して初めて、bounds を完了済みにする。
親が init を定義せず、フィールドの既定値も与えない場合は、モデル定義をエラーにする。

未完了フィールドは、フィールド全体への初回代入の対象としてだけ使用できる。
読み取り、添字、メソッド呼び出し、ref、入力先、子フィールドだけへの書き込みは禁止する。
`this.bounds.width = ...` のような部分更新で完了扱いにはしない。
既に完成している適切な型の値を、値コピーで全体代入する方法も許可する。

未完了フィールドが残っている間は、this 全体のコピー・表示・比較・ref 渡し・メソッド呼び出しを禁止する。
一方、完了済みの個別フィールドと、その入れ子のメソッドや ref は通常の規則で利用できる。
init 内の this.addr と this 全体への代入は、完了状態にかかわらず禁止する。
未完了フィールドを別名から操作して検査を回避することを防ぐ。

void の return / 本体末尾、bool の成功 return に至る全経路で、全フィールドの完了を証明する。
if の合流では全ての到達経路で完了したフィールドだけを完了済みとする。
実行されない可能性のあるループ本体の代入だけでは、ループ後の完了を証明したことにしない。
bool の `return false` では未完了フィールドを残せるが、生成済み file の close は第10節どおり必要。
戻り値が false と確定しない bool の return には、成功の可能性があるため完了の証明を要求する。
未使用の init や到達不能な式でも、不正なフィールド利用と型・公開範囲は検査する。

全フィールドが完成した後は、this を通常のメソッドや補助関数へ渡せる。
init の作者が呼び出した処理は、その時点の値を観測できる。
コンパイラが保証するのは型としての初期化完了であり、任意の業務上の不変条件まで自動で検証するものではない。
最終的な生成可否は init の本体で判断する。

## 7. 引数なしの生成と配列

引数を全て省略でき、必要なフィールドの初期化手順が有効な場合に、引数なしで生成できるとする。
bool init の成功をコンパイル時に保証する必要はなく、false なら実行時に生成を拒否する。

| 操作 | init の扱い |
| --- | --- |
| `Point p` / `Point p = {}` / `Point p = Point()` | 引数なしの生成を1回行う |
| `Point copy = source`、値引数、戻り値 | 全状態をコピーし、init は実行しない |
| `Point points[2]` | 各要素について引数なしの生成を1回ずつ行う |
| `Point points[] = []` | 要素を生成しない |
| `points.add()` | 既定の要素を1つ生成し、成功後に追加する |
| `points.add({x=3.0})` | 指定した入力で生成し、成功後に追加する |
| `points.add(existing)` | 既存値のコピー。init は実行しない |
| モデル配列のコピー | 各既存要素をコピーし、init は実行しない |

Rectangle のように必須引数がある型では、`Rectangle rect`・`Rectangle()`・`rectangles.add()` はエラー。
一方、空の配列と、引数を全て与えた要素の配列リテラルは許可する。

```text
Rectangle rectangles[] = []
rectangles.add({width=3.0, height=4.0})
Rectangle fixed[2] = [{width=1.0, height=2.0}, {width=3.0, height=4.0}]
```

上限付き配列の宣言で不足分を埋める場合は、埋める各要素の引数なしの生成が必要。
必須引数のある型では、全要素が与えられることを証明できない初期化を拒否する。
`Rectangle fixed[2] = [{width=1.0, height=2.0}]` はエラーになる。
実行時の長さしか分からない配列で、既定生成が必要になる可能性を隠さない。
既存値の単純な再代入や、埋め合わせを行わない配列コピーは、生成と区別して扱う。

多次元配列でも実際に不足するモデル要素だけに適用する。
`Rectangle rows[2][0]` のように末端のモデル要素が0個なら、Rectangle の既定生成は要求しない。
未完了になる上限付き配列フィールドは、親の init で全体を完成させる第6節の規則を使う。

配列への追加では、要素の生成成功前に配列の長さを増やさない。
添字・更新対象は1回だけ評価し、既存の参照中の所有元変更・配列再配置の検査も維持する。

## 8. 検証失敗

bool init が false を返した場合、その生成式は完成したモデル値を返さない。
生成位置とモデル名を示す実行時エラー70で停止する。
例: `Rectangle の初期化が拒否されました`。
不正な入力がリテラルでも、ユーザーの init をコンパイル時に実行して判断しない。

false をゼロ値のモデルに置き換えたり、生成先へ未完了の値を入れたりしない。
この実装単位では、生成失敗の捕捉・例外・結果型・try 構文は導入しない。
失敗から回復する処理が必要な場合は、通常関数で入力を検査してから生成する。
将来は同じ init の成功・拒否を利用できる結果型などを設計する。

bool init は、file.open などの実行時エラーを自動で捕捉する仕組みではない。
不正 UTF-8、I/O 失敗、範囲外アクセスなどは現在の実行時エラーの規則に従う。
外部への副作用と、途中まで完成した別のオブジェクトを巻き戻す保証は追加しない。

## 9. const・readonly・コピー・公開範囲

init は生成時に実行する通常の処理であり、const のコンパイル時計算では実行しない。
初期段階では、init を持つモデルと、その型をフィールド・配列経由で含むモデルは const の対象から除外する。
モデル要素型に init があれば、空の const モデル配列も同じ型規則で拒否する。
init を持たない従来のモデルの const は維持する。
定数生成対応の init は、後続の定数評価の設計で別途扱う。

生成後は、現在と同じ値型として振る舞う。
init を実行せずに既存値をコピーでき、private を含む全状態を保つ。
readonly メソッドや ref readonly 引数から読む規則も変わらない。
readonly の file をコピーして持ち出すことは、生成式の引数でも従来どおり拒否する。

init の引数名は公開する生成APIである。内部のフィールド名だけの変更とは異なり、引数名の変更は呼び出し元へ影響する。
private フィールドの設定は init 本体で行い、引数名に private のアクセス権は不要とする。
モデル型の同一性、import / using / 別名、既定値の宣言位置のアクセス権は維持する。
同じ綴りの別モデルの init や private メンバーを混同しない。

## 10. file と明示 close

init 内では、通常のメソッドと同じく file.open を使える。
成功時に this のフィールドへ保持した新しいハンドルは、生成された値とともに呼び出し元へ責任を渡す。
呼び出し元は、public close メソッドなどを介して正常終了の全経路で明示 close する。
生成時に開いたことや private フィールドであることは、close の免除理由にならない。

```text
model HeaderReader;
	private file handle
	private str first_line

	public bool init(str path);
		this.handle = io.file.open(path, "r")
		if(not(io.file.readline(this.handle, ref this.first_line)));
			io.file.close(this.handle)
			return false
		return true

	public readonly str header() = this.first_line

	public void close();
		io.file.close(this.handle)

int main();
	HeaderReader reader = {path="input.txt"}
	io.print(reader.header())
	reader.close()
	return 0
```

bool init の false の通常 return では、生成された値へ責任を渡さない。
その時点で init・フィールドの既定生成が新規取得したハンドルは、全て明示 close が必要。
上記の false 経路の close を削除するとコンパイルエラーにする。
未完了フィールドがあっても、完了済みの子モデルの close は呼べる。

成功経路でも、this へ保持せずローカルだけに残したハンドルは close が必要。
bool の return 式の真偽を証明できない場合は、成功・拒否の両方として解析する。
close していない所有リソースを保持したまま `return valid` とする形は、false 経路を証明できなければ拒否する。

init の引数は file を含まない値に限定するため、生成拒否の清掃で呼び出し元の共有ハンドルを閉じる必要を生じさせない。
既存ハンドルを受け取る生成APIは、借用・所有権の契約を設計する後続の拡張とする。
init を持たないモデルの従来の file フィールド初期化や通常メソッドの共有規則は維持する。

既存のモデル変数へ新しいモデルを代入しても、以前のハンドルは自動で閉じない。
以前の値も明示 close が必要。コピーしたモデルの file は引き続き共有ハンドルとなる。

途中の入れ子生成などが実行時エラーでプロセスを停止する場合は、既存の異常終了の規則に従う。
正常 return の明示 close 検査と、異常終了時の自動ロールバックを区別する。
例外や自動デストラクタ、正常終了時の暗黙 close は今回追加しない。

## 11. 診断とVSCode

コンパイル診断は、引数の不足・未知名・重複・型不一致、未完了フィールドの利用、
成功時の初期化漏れ、既定生成の循環、const の制約、close 漏れを区別する。
生成位置と init / フィールドの宣言位置を示す。
実行時の生成拒否では、配列の不足分生成や入れ子でも、元の生成位置を保持する。

VSCode では `{...}` の型を判定できる位置で init 引数名を候補にする。
init がある型ではフィールド名を生成引数の候補へ混ぜず、必須引数・型・既定値を表示する。
init のない型では、従来の公開範囲を満たすフィールドを対象とする。
通常の `rect.` のメソッド補完には init を出さず、アウトラインには生成処理として表示する。
引数名のホバー・定義参照は init 引数へ移動する。
通常の関数・メソッドの引数一覧に既定値を追加する機能と混同しない。
型を推論できない未完成の式は、既存どおりコンパイラの検査に委ねる。

## 12. 実装方針

1. モデルに専用の initializer 定義を保持する。通常のメソッド検索とモジュール公開関数からは分離する。
2. 引数の既定値の構文と、モデル生成に対する名前付き引数の対応付けを追加する。
3. 型解決後に `{...}` を、従来のフィールド初期化と init 呼び出しへ分類する。ユーザーから直接利用できない内部のフィールド初期化を別のノードにする。
4. 初期化本体の this に、未完了フィールドの状態を保持する。分岐・return を含む完了検査を行い、別名や内部形式への変換で状態を失わないようにする。
5. 未完了フィールドの初回代入は、旧値を読み取る通常の再代入と分ける。モデルのゼロポインタへの借用検査や、未生成配列の shape の読み取りを発生させない。
6. 通常生成・引数なしの生成・未完了領域の確保・既存値のコピーを分離する。配列の不足分と add() も正しい入口を使い、コピー用の補助処理から init を再実行しない。
7. 既定生成の依存関係を検査し、実行時の生成が必要な既定値を定数評価のキャッシュへ入れない。const の対象型を再帰的に検査する。
8. 引数・生成途中の領域・入れ子をGCの対象として保持し、配列上限と既存の借用制約を維持する。
9. init の bool / void の結果を完成したモデル値へ変換する専用の呼び出しを生成する。生成位置の診断情報を内部引数などで保持し、入れ子や動的な配列生成でも失わないようにする。
10. close 解析に、成功時に this から返るハンドルと、false の return で返してはいけないハンドルを区別した要約を追加する。フィールドの既定生成も含めて責任を追跡する。
11. VSCode の候補・引数表示・定義参照・アウトラインと仕様書を更新する。

既存のコピー処理でゼロ値を受け取ったことを、無条件にユーザーの既定生成と見なさない。
必須引数・未完了フィールド・init の副作用・コピーが、それぞれ別の意味を持つように実装する。

## 13. 受け入れ条件

- init のない既存モデルの生成・const・コピー・公開範囲を維持する。
- void / bool init、private フィールドへの設定、名前付き引数、既定引数が動作する。
- 明示引数は記述順、既定引数は宣言順で、スナップショットを含めて1回ずつ評価する。
- 生成・再代入・値引数・戻り値・配列・add・フィールド既定値で同じ生成規則を使う。
- コピー・値引数へのコピー・配列コピー・既存要素の add では init を再実行しない。
- 必須引数不足、未知名、重複名、型や次元の不一致、直接の init 呼び出しを拒否する。
- init の重複、private / readonly、戻り値型、数式形式、引数の ref と file 含有型を診断する。
- 必須引数のある子モデル・配列フィールドを、親の init 内で全体代入により完成できる。
- 初期化前の読み取り・部分更新・ref・this 全体の利用・別名作成を拒否する。
- 全ての成功経路でフィールドが完成し、false の経路だけなら未完了を許可する。
- 不足分を補う配列の生成、空配列、多次元の末端0要素、add() を区別する。
- 既定引数・フィールド既定値の生成循環を診断し、型・深さ・定数展開の既存の上限を維持する。
- init と再帰的にそれを含む型を const として生成せず、readonly と独立した値コピーは維持する。
- bool false を実行時エラー70にし、配列を含めて生成位置を示し、未完了値を生成先へ渡さない。
- 成功時の file 所有責任を呼び出し元へ渡し、false とローカルの close 漏れを拒否する。
- 入れ子の file、早期 return、配列、コピー、生成済みの値の再代入でも close の責任を追跡する。
- GC多発時、Linux / Windows、アセンブリ出力、VSCodeの生成引数補完を検証する。

実装時は個別検証の後、最終確認として全体テストを1回実行する。
専用テストは `make test-initialization`、実行例は `examples/models/initialization.qy`。
