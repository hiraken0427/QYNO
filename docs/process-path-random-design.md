# 作業ディレクトリ・実行時引数・乱数（新段階13〜15、設計）

状態: 新段階13（作業ディレクトリ・絶対パス）は0.27.4で実装済み。
新段階14（実行時引数・voidマーカー）と15（乱数）は設計案であり未実装。
後続の実装時のバージョンは別途決定する。
パスは既存のstr、引数一覧は既存のstr配列、乱数生成器は標準modelを使う。
新しいPath型・ポインタ・汎用例外・関数オーバーロードは追加しない。

## 1. 設計開始時の実装状況（0.27.3）

- io.pathの基本9関数はパス文字列の分解・結合・整理だけを行う。
- 作業ディレクトリを取得・変更するAPIはない。実行時の相対ファイルパスは、起動したプロセスが引き継いだ作業ディレクトリを基準にする。
- エントリ関数は明示したint戻り値・引数なしに限定される。通常は`int main();`と記述する。
- `main(void)`はまだ構文として許可されない。void / Void自体は値`()`を持つ既存の型である。
- 標準の乱数APIはない。

## 2. 名前空間とusing

io.dir、lib.randomはimport不要の標準サブモジュールとする。
裸の名前にはusingが必要で、usingは子モジュールの中を再帰展開しない。

| 記述 | 動作 |
| --- | --- |
| `io.dir.current()` | import・usingなしで利用 |
| `using io.dir as dir` | `dir.current()`・`dir.change(...)` |
| `using io` | `dir.current()`は可、`current()`は不可 |
| `lib.random.int(1 <= i <= 6)` | import・usingなしで利用 |
| `using lib.random as random` | `random.int(...)`・`random.Random` |
| `using lib.random` | 型名int等と衝突するため診断。モジュール別名またはusing libを使用 |
| `using lib` | `random.int(...)`が可。裸のintは既存の型変換のまま |

lib.size / lengthの意味は変更しない。lib.randomはlib配下の独立した汎用機能として追加する。

## 3. 作業ディレクトリと絶対パス

以下は組み込みAPIの説明用シグネチャである。

| API | 戻り値 | 意味 |
| --- | --- | --- |
| `io.dir.current()` | str | 現在のプロセスの作業ディレクトリを絶対パスで取得 |
| `io.dir.change(str path)` | void | 指定した既存ディレクトリへ作業ディレクトリを変更 |
| `io.path.absolute(str path)` | str | 呼び出し時の作業ディレクトリを基準に、完全な絶対パスを組み立てる |

currentは実行ファイルの配置場所、ソースファイルの場所、importの探索ルートとは別である。
changeはQYNOプロセス全体に作用し、呼び出し元のシェルの作業ディレクトリは変更しない。
実行ファイルの配置場所を返すAPIは、この初版には含めない。

### current

- 結果はstrのスナップショット。後のchangeによって既に取得した文字列は変化しない。
- 既存のio.pathに合わせ、Windowsでは区切りを`/`として返す。ルート以外の末尾区切りは除く。
- LinuxはOSから取得した実際の作業ディレクトリを返し、環境変数PWDの文字列は信用しない。
- Windowsのドライブ絶対パスとUNC共有パスを扱う。大文字小文字・Unicodeの正規化はしない。
- ディレクトリの削除等で取得不能ならio.Error。空文字や古い値で代用しない。
- 固定長PATH_MAXバッファには依存せず、OSの必要サイズに応じて拡張する。

### change

- 絶対パスと、現在の作業ディレクトリからの相対パスを受け取る。`.`・`..`も使用できる。
- 実在するディレクトリのみ受け付ける。作成やシェルの実行はしない。
- シンボリックリンク等の辿り方はOSに従う。呼び出す前に`..`を文字列処理で潰さない。
- 成功したら通常の戻り値`()`。OSが変更を拒否した場合は元の作業ディレクトリを保持する。
- 変更後にcurrentを呼んで戻り値を作る処理は挟まない。変更自体は成功したのに取得失敗でchangeも失敗したように見える事態を避ける。
- `""`、埋め込みNUL、Windowsデバイス名前空間は引数エラー70。定数で分かればコンパイルエラー。
- `~`、環境変数、ワイルドカードは展開しない。
- Windowsでは`C:/work`と`//server/share/work`を許可する。ドライブ相対`C:work`と、ルート相対`/work`・`\work`は初版では拒否する。通常の`work`・`../work`は許可する。
- OSへ渡す文字列の変換は既存のfile APIと共通にする。Windowsの通常パスの解釈はWin32に従い、デバイス名前空間はユーザー入力から直接通さない。

### absolute

- 対象ファイルやディレクトリの存在を要求しない。ファイル作成先にも使える。
- 完全な絶対パスなら既存normalizeと同じ整理だけを行い、currentを取得しない。
- 相対パスならcurrentと結合する。空文字は`.`と同じで、現在のディレクトリになる。
- 重複区切りと`.`は整理するが、`..`は保持する。例えば`/work/../data`も絶対パスである。
- リンク解決、実在確認、アクセス権の保証はしない。strictな実体パス解決は後続のresolveとして分ける。
- Windowsのドライブ相対・ルート相対はchangeと同様に拒否する。
- 既存の基本9関数は純粋な文字列操作のまま。absoluteは実行時の作業ディレクトリに依存するので、絶対パス引数でもconst式には使用しない。

### 他の処理への影響

- 変更後にopenする相対ファイルパスは新しい作業ディレクトリが基準になる。
- 既にopenしたfileの参照先・現在位置・close責任は変わらない。
- mainに渡す相対パスの引数は単なる文字列。changeしても引数を自動で書き換えない。
- 起動時基準で扱いたい入力はchangeの前にabsoluteへ変換する。
- importはコンパイル時に解決済みで、実行時のchangeの影響を受けない。
- 一時移動は、呼び出し側が元のパスを保存し、finallyで戻す。復帰失敗も通常のio.Errorとして扱う。
- 将来並行処理を導入する場合にも、changeはプロセス全体に作用する。タスクごとの作業ディレクトリにはしない。

```text
using io
using io.dir as dir
using io.path as path

int main();
	str before = dir.current()
	str target = path.absolute("../data")
	try(dir.change(target)) as error;
		print(dir.current())
	case();
		print("{error.operation}: {error.message}")
		return 1
	finally;
		dir.change(before)
	return 0
```

## 4. ディレクトリのエラー

- OS失敗は既存のtry / case / finally / io.Errorへ統合する。未処理なら既存どおり終了74。
- 不正UTF-8は65、引数の契約違反は70。これらをOS失敗のcaseで捕捉する仕様には変えない。
- not_found、permission_denied、invalid_path、unsupported_operation、system_error等を再利用する。
- 既存の0〜14を変更せず、`io.ErrorCode.not_directory = 15`を末尾へ追加する。
- changeで途中または最後の要素がディレクトリでない失敗をnot_directoryへ分類する。既存file APIのENOTDIR分類は変更しない。
- operationはcurrent / change / absolute。pathはchangeの元の引数、absoluteの元の引数、currentでは空文字とする。
- absolute内でcurrent取得に失敗しても、公開呼び出しabsoluteのソース位置・operationを残す。
- OSから返ったパスがstrへ厳密に変換できない場合はデータエラー65。置換文字で別のパスにしない。
- ディレクトリの名前変更・削除等の外部変更に対するトランザクションは保証しない。

## 5. mainの実行時引数

次の3形式を許可する。戻り値は引き続き明示したintとする。

```text
int main();
	return 0
```

```text
int main(void);
	return 0
```

```text
int main(str args[]);
	for(0 <= i < args.length, i++);
		io.print(args[i])
	return 0
```

上記は選択肢であり、同一プログラムでmainを複数定義することはできない。
argsという名前は自由で、`str arguments[]`等でもよい。

### argsの内容と型

`./main.exe alpha "two words" ""`で起動した場合は次のとおり。

| 式 | 値 |
| --- | --- |
| args.length | 3（int_64） |
| args[0] | `"alpha"` |
| args[1] | `"two words"` |
| args[2] | `""` |

- 実行ファイル名を含めない。引数なしなら空配列。終端のnull要素はない。
- すべて通常のUTF-8 str。数字、パス、オプション名を自動で型変換しない。
- 通常の値引数で、配列の変更・add等はmainのローカルな値を変更する。OSのコマンドライン自体を書き換えない。
- `argc`はargs.lengthと重複するので初版では追加しない。
- `main(int argc, str argv[])`、固定要素数、多次元、ref / readonly、auto、既定引数は初版のエントリ形式として拒否する。
- mainを他のQYNOコードから呼び出すことは引き続き禁止する。
- no-args形式でも追加の実行時引数があること自体はエラーにせず、引数配列を作成しない。
- `--`、`--help`等もQYNOランタイムは解釈しない。qyc自身のオプションとは別である。
- 実行シェルが行う展開はシェルの責任。QYNOは追加の変数展開・glob・空白分割を行わない。

### OS別の取り込み

- Linux: エントリ時のargc / argvを保存し、argv[1..]を厳密なUTF-8として読み取る。引数境界を保持する。
- Windows: GetCommandLineWから取得し、MSVC CRTに準拠した引用符・バックスラッシュ処理を行う。先頭の実行ファイル部分にはCRTの専用規則を適用して除く。
- Windowsでは引数部分の引用符外のスペース・タブで分割し、`""`を空引数として保持する。引用符直前の2n個のバックスラッシュはn個と引用符の構文、2n+1個はn個と文字としての引用符になる。引用符内の連続した引用符・末尾バックスラッシュもCRTの規則に合わせる。
- Windowsの不対UTF-16サロゲートとLinuxの不正UTF-8を黙って置換しない。
- 型付きargs形式で取り込みに失敗した場合はmain実行前に診断する。不正な文字列は65、メモリ不足・サイズ超過は既存の70。main内のtryでは捕捉できない。
- 引数配列と各文字列は通常のGC管理領域に構築し、初期化中もルートを保持する。OSの領域を可変な配列として公開しない。
- 文字列や配列サイズの加算・乗算を検査し、固定バッファやint32への引数個数の切り捨てをしない。

## 6. `(void)`による引数なしの明示

mainに限らず、通常関数・メソッド・interface契約・initにも適用する。

| 定義 | 意味 | 呼び出し |
| --- | --- | --- |
| `void show();` | 引数なし | `show()` |
| `void show(void);` | 引数なし。上と同じ | `show()` |
| `void show(Void);` | 引数なし。型の別名も同じ | `show()` |
| `void show(void value);` | void型の値引数1個 | `show(())` |

- 開き括弧の直後にvoid / Voidが1個だけあり、その次が閉じ括弧の場合に限り、空の仮引数リストへ正規化する。
- `void`という型・値`()`・名前付きvoid引数・void配列の既存仕様を維持する。
- メソッドの暗黙thisは消さない。明示引数が0個であることを表す。
- `(void, int x)`や`(ref void)`のような名前のない型を含むリストは拒否する。
- 呼び出し側は常に`show()`。`show(void)`という呼び出し構文は追加しない。
- interfaceの実装照合では`()`と`(void)`を同じ契約とする。ABIにも追加スロットを作らない。

## 7. 型名と不等式を使う乱数API（改訂案）

利用者の指示に従い、integer / real / real_quad / boolean / bitsという公開名は撤回する。
戻り値を型名から判断できるようにする。以下のrandomはlib.randomの別名である。

```text
using lib.random as random

int main(void);
	int dice = random.int(1 <= i <= 6)
	int index = random.int(0 <= i < 10)
	double ratio = random.double(0 < x < 1)
	bool enabled = random.bool()
	int_64 signed_bits = random.int_64()
	unsigned int_64 unsigned_bits = random.unsigned_int_64()
	char letter = random.char("ABCDEF")
	str token = random.str(8, "ABCDEF0123456789")
	return 0
```

| API | 戻り値 | 範囲省略時・指定方法 |
| --- | --- | --- |
| int_8 / int_16 / int / int_32 / int_64 / int_128 | 名前と同じ符号付き整数型 | 引数なしなら型の全域。不等式で範囲指定可 |
| unsigned_int_8 / unsigned_int_16 / unsigned_int / unsigned_int_32 / unsigned_int_64 / unsigned_int_128 | 対応するunsigned整数型 | 引数なしなら型の全域。不等式で範囲指定可 |
| half / float / double / quadruple | 名前と同じ小数型 | 不等式で有限範囲を必ず指定 |
| bool() | bool | false / trueを各1/2で生成 |
| char() / char(str candidates) | char | 既定の印字可能ASCII、または候補から1書記素クラスタ |
| str(int_64 count) / str(int_64 count, str candidates) | str | 指定個数の文字を生成。初版の候補は印字可能ASCII |
| seed(unsigned int_64 value) | void | 共有生成器のシードを指定 |

- intとint_32は同じAPI・戻り値・生成列の別名とする。unsigned_intも同様。
- unsigned int_64は空白を含む複合型名なので、API名では機械的にunsigned_int_64とつなぐ。新しい型名の別名は追加しない。
- int_64()は-2^63〜2^63-1。64bit全体のパターンを使うが、結果は負数も含む。
- 0〜2^64-1が欲しい場合はunsigned_int_64()を使う。旧bits()は不要になる。
- 小数の既定範囲は設けない。double()のような範囲省略は拒否し、double(0 <= x < 1)等と書く。
- 複素数は不等式で順序を定義できないため初版には含めない。void / addr / fileの乱数も用意しない。
- 戻り値の型は代入先で変化しない。int()とint_64()を使い分ける。

### 不等式は範囲指定の構文

```text
random.int(min < i <= max)
random.int(min <= i < max)
random.int(min <= i <= max)
random.double(min < x < max)
random.int(10 > i >= 0)
```

- 乱数APIの範囲引数として、2つの不等号で単独の識別子を挟む構文を追加する。
- 中央のi / xは生成する値を示す局所的な仮の名前。事前宣言は不要で、外側の同名変数を読み書きしない。
- 実行時にこの識別子を評価・代入せず、スコープへ変数も追加しない。中央値に型宣言・添字・式は許可しない。
- 中央の名前は両端の式では参照不可。同名の外側変数を境界で使いたい場合は、中央を別名にする。
- 両端には通常の数値式・関数呼び出しを指定でき、ソース上の左から右へ各1回だけ評価する。
- `<` / `<=`、または逆向きの`>` / `>=`を組み合わせる。10 > i >= 0は0 <= i < 10と同じ範囲。
- `a < i > b`のように上下限を作らない形、3個以上の比較、== / !=、and / orでつないだ条件は拒否する。
- `bool condition = 0 < i < 10`のように通常のbool式を作って渡すことはできない。
- 専用の範囲ASTとして解析し、既存の短絡する比較式として実行しない。一般の連鎖比較やforの意味は変更しない。
- min / maxを第1・第2引数で渡す旧形式は導入しない。生成される値の名前は範囲内の説明だけに使う。

### 整数の境界

- 整数型の境界は整数値のみを受ける。bool・小数・複素数を黙って整数化しない。
- 不等式の整数解と戻り値型の表現範囲との共通部分から一様に選ぶ。境界は先に狭い戻り値型へ変換しない。
- 例: int(0 < i < 5)は1 / 2 / 3 / 4、int_8(-200 <= i <= 200)は-128〜127。
- 符号付き・符号なしの境界も数学的な値として比較し、負数を巨大なunsigned値へ読み替えない。
- 型の最小値・最大値の外側を扱う比較と排他的境界の補正は、多倍長または等価な桁上がり付き内部計算で行う。
- 候補が1個ならその値を返し、生成器を進めない。空集合なら引数エラー70。定数で分かる空集合はコンパイルエラー。
- 例えばint(0 < i < 1)は空集合であり、小数へ戻り値型を変更することはない。

### 小数の境界と有限精度

- 境界リテラルは呼び出した型の文脈で解釈する。他の式は既存の数値変換規則を使い、必要な縮小変換は利用者が明示する。
- 境界は有限値のみ。NaN / 無限大、逆転、等号のない同一境界等は拒否する。
- 開いた端点は絶対に返さず、閉じた端点は生成可能にする。閉区間の端点が毎回出ることを保証する意味ではない。
- 各型が表現できる値で条件を満たすか確認する。隣接する小数値の間の開区間など、実数では空でなくても候補がない場合はエラーにする。
- 候補が1個なら生成器を進めず返す。0の符号違いは候補2個として数えず、数値としての0として扱う。
- 連続一様分布を有限精度の格子で近似する。浮動小数点の全ビットパターンを同確率で選ぶ仕様ではない。
- 仮数精度pはhalf=11、float=24、double=53、quadruple=113。乱数の計算をdoubleへ統一して精度を落とさない。
- 補間用uの格子は、[0,1)ならk=0..2^p-1、(0,1)なら1..2^p-1、[0,1]なら0..2^p、(0,1]なら1..2^pとし、u=k/2^p。kは棄却法で偏りなく選ぶ。
- (1-u)*min+u*maxに対応する値を計算し、戻り値型へ丸める。途中のmax-min等を安易に計算してオーバーフローさせない。内部補間の丸め規則もターゲット間で固定する。
- 丸めによって開いた端点へ到達した値は棄却して再生成する。端点へのクランプで確率を集めない。候補なし・1個の検出は抽選前に行う。
- 補間は境界を符号・整数仮数・二進指数へ分解し、(2^p-k)*min+k*maxを必要桁数の内部整数で計算して2^pで割る。最後に1回だけ戻り値型へ最近接・偶数丸めする。IEEE各型の指数範囲で必要桁数を制限できるため、無限精度の外部ライブラリやFMAの有無に依存しない。

### charとstr

- char()の既定候補はU+0020〜U+007Eの95文字。制御文字・NULは含めない。
- char(candidates)は候補strを既存のUnicode 17.0.0の書記素クラスタで分割し、その位置を一様に選ぶ。日本語・絵文字・結合文字を使える。
- 同じ文字が複数位置にあればその回数だけ重みが増す。空候補はエラー。候補を勝手にソート・重複除去・正規化しない。
- str(count, candidates)は独立した復元抽選をcount回行い、結果を連結する。countは0以上のint_64。
- 初版のstrの候補は印字可能ASCIIに限定し、戻り値.length=countを保証する。候補省略時はchar()と同じ95文字。
- Unicodeのクラスタは連結で結合しうるため、charで使える全候補をstrでも無条件には受け付けない。Unicode対応のstr生成は、長さの契約を別途設計する後続項目とする。
- 候補の検証と出力サイズの検査は抽選前に行う。count=0なら空文字を返し、乱数の消費・自動シードを行わない。空候補などの不正指定はcount=0でも拒否する。
- char / strは通常の値であり、出力や補間に特別な処理は不要。暗号用トークンとしての安全性は提供しない。

### 名前解決と型変換の衝突

- 完全修飾lib.random.int、using libによるrandom.int、モジュール別名を使う。
- 裸のint(...) / double(...) / char(...) / str(...)は既存の型変換の意味を維持する。
- 型名であるメンバー呼び出しを、ドットと解決済みの所有者を見て解析する。予約語を一般の変数名として開放しない。
- 型名と衝突する関数の選択usingと、別名なしusing lib.randomは診断し、モジュール別名を案内する。型変換を乱数へ上書きしない。
- seedやRandomのように型名と衝突しないシンボルの選択usingは従来の規則で扱う。

### 共有生成器と明示シード

- 最初の値生成時にだけOSから8バイトのエントロピーを取得し、64bitシードとして使用する。
- それより前にseed(value)を呼んだ場合はOSの乱数取得を行わない。再現可能な実行にできる。
- OSのエントロピー取得失敗はio.Errorで回復可能にする。時刻・PID等への暗黙の代替は行わない。
- 共有状態はプロセスごとに1つ。importやusing、関数の呼び出しごとには作り直さない。
- 明示的な固定シードはテスト用、自動シードは通常用途を基本とする。
- 共有状態を変更する関数はconst式に使えない。明示シード後の値生成にOS呼び出しは不要。

### 独立したRandom model

```text
using lib.random as random

int main(void);
	random.Random dice = {seed=42}
	random.Random same = dice
	io.print(dice.int(1 <= i <= 6))
	io.print(same.int(1 <= i <= 6))
	return 0
```

- initはunsigned int_64 seed=0を受ける。省略シードは固定の0であり、OSから自動取得しない。
- 共有APIと同じ型名・範囲構文・戻り値のメソッドを提供する。seedも同様。
- 状態はprivate。値コピーすると現在の生成状態を複製し、その後は独立して進む。上の2行は同じ結果を表示する。
- 関数内で呼び出し元の生成器を進める場合はref random.Randomで渡す。通常の値引数はコピーを進める。
- 生成・再シードは状態変更なので、constの生成器・ref readonly・readonlyメソッド経由では拒否する。
- 配列・modelフィールドとしても既存の値・初期化規則を適用する。各要素を同じシードで初期化すれば同じ列になる。
- 型名をメソッド名として解釈する処理は、この標準型の解決済みメンバーに限定する。利用者の通常メソッドの命名規則は変更しない。

## 8. アルゴリズムと再現性

初版はxoshiro256**とし、64bitシードをSplitMix64の連続4出力で256bit状態へ展開する。
OSごとにCライブラリのrandへ委譲せず、出力列を公開仕様として固定する。
アルゴリズム変更で同じseedの列を黙って変更しない。将来は別の生成器型として追加する。
これはシミュレーション・ゲーム・テスト用で、暗号鍵・認証トークン用にはしない。

- xoshiro256**は公開されている参照実装の出力・更新順に従う。出力はrotl(s1 * 5, 7) * 9。
- SplitMix64は状態へ0x9e3779b97f4a7c15を加算し、xor / 右シフト30、乗算0xbf58476d1ce4e5b9、xor / 右シフト27、乗算0x94d049bb133111eb、xor / 右シフト31の順で出力する。
- すべての内部演算はunsigned 64bitのmod 2^64。QYNOの通常の範囲検査付き整数演算とは区別した内部実装にする。
- シード0も有効。256bitの全0状態を作らない。
- Nbit整数の全域は乱数のNbitパターンを一様に対応させる。128bitでは連続2語を上位・下位の順で連結する。64bit未満は1語の上位Nbitを使う。
- 符号付き全域はビットパターンを2の補数として解釈し、boolは1語の最上位bitを使う。
- 範囲付き整数は正規化した閉区間[L,U]のspan=U-L+1を扱い、剰余バイアスを除く棄却法を使う。span=2^Nも折り返さない。
- 各型のNbit候補rについてthreshold=2^N mod spanとし、r<thresholdなら棄却、L+(r mod span)を返す。全域の場合は引数なしのAPIと同じビットパターン対応にする。
- 小数の生成方法は第7節の型別精度と端点規則に従う。boolや整数の生成器を別に持たず、同一の状態を進める。
- charは候補数に対する偏りのない整数抽選、strはこれを指定回数行う。
- 不正な範囲・文字候補・出力サイズは抽選前に検査し、検査失敗で生成器を進めない。引数式自体の副作用は通常どおり残る。
- 自動シード失敗時も共有生成器は未初期化のまま保つ。
- 同じシード・同じAPI呼び出し順・同じ引数なら、Linux / Windows / -Sで同じ結果を返す。
- 小数を後から狭い型へ丸めた結果まで元の端点条件を保証するものではない。各API本来の戻り値型で条件を保証する。

## 9. OS連携と既存の検査への統合

| 対象 | Linux | Windows |
| --- | --- | --- |
| current | getcwd syscall、必要サイズに応じ再試行 | GetCurrentDirectoryW、UTF-16から厳密変換 |
| change | chdir syscall | SetCurrentDirectoryW |
| 実行時引数 | エントリスタックのargc / argv | GetCommandLineWとCRT互換の独自分割 |
| 自動シード | getrandom、短い読み取りとEINTRを処理 | BCryptGenRandomのシステム優先RNG |

- Windowsの自動シードはBCryptGenRandomを使い、bcrypt.dllの複数DLLインポートにPE出力を拡張する。NTSTATUSをGetLastErrorとして解釈せず、RtlNtStatusToDosErrorでWin32コードへ変換してError.os_codeへ残す。変換不能なら元のステータスをメッセージにも残す。
- Windowsのコマンドライン分割はShell32への追加依存を必要としない構成にする。
- current / change / absolute、共有乱数の値生成は、回復可能な失敗の効果解析とfileのclose解析に統合する。
- 自動シード失敗はErrorCode.system_error、OS機能自体が未対応ならunsupported_operation。pathは空文字、operationはint / double等の公開呼び出し名とし、seed内部の位置に置き換えない。
- Randomの明示シード操作はOSに依存しない。引数範囲の不正はtryで回復するOS失敗にしない。
- 生成器の状態・mainの引数・currentの戻り値をGCルートとして適切に扱う。
- -S経由の生成と直接実行ファイルの生成を一致させる。クロスコンパイル時にはホストの作業ディレクトリ・引数・乱数を埋め込まない。

## 10. 追加する検証

- ディレクトリ: 絶対・相対・`.`・`..`・ルート・UNC、日本語・絵文字、長いパス、空文字、NUL、ファイル指定、存在しない対象、権限、失敗時の現在位置維持。
- absolute: 存在しない出力先、リンクを含む`..`の保持、変更前後の基準、既存9関数の定数評価維持、Windowsの曖昧なルート拒否。
- file連携: change前に開いたハンドルの参照先維持、change後の相対open、finallyの復帰と復帰失敗、例外経路のclose検査。
- main: 0個・複数・空引数・空白・タブ・引用符・バックスラッシュ・Unicode・無効エンコード、多数・長い引数、引数配列のコピーとGC。
- Windows分割: MSVC CRTの小さな参照プログラムと固定テスト表を使い、実際の引数境界・空引数・末尾バックスラッシュを照合する。
- void: `()`と`(void)`の等価性、Void別名、名前付きvoid値、メソッドのthis、interface照合、init、誤った引数リストの拒否。
- 乱数: 参照実装から独立に固定した出力ベクトル、seed0 / 最大値、コピーとref、全域・1要素・範囲エラー、棄却を確実に通す内部テスト、全整数型の幅・符号、4種類の小数の格子と全端点、空の表現可能集合、Unicodeのchar・ASCIIのstrと長さ。
- 実行時間や小さい標本の分布だけを合否条件にしない。共有自動シードはOS失敗・短い読み取り・EINTRを注入し、状態保持と公開呼び出し位置も検証する。
- Linux / Windowsの実行、-S、GC頻発、VS Codeの新API・main引数・voidマーカー・Randomメソッドの補完と診断。
