# 文字列の標準メソッド（新段階16、0.27.7）

状態: 0.27.7で実装済み。const評価とLinux / Windowsの生成コードで共通処理を使用する。
既存の[Unicode書記素クラスタと文字列](graphemes-void.md)の仕様を拡張する。
初版は検索・前後判定・空白除去・分割・置換の7メソッドとする。

## 1. 公開API

str / charの組み込みメソッドとして提供し、import / usingを必要としない。
以下のtextは受け手の値、value / separator / old / newはstrまたはcharの値を表す。
表はAPIの説明用であり、新しい共用型やメソッド定義構文を追加するものではない。

| 呼び出し | 戻り値 | 意味 |
| --- | --- | --- |
| text.contains(value) | bool | 一致する部分を含むか |
| text.starts_with(value) | bool | 先頭から一致するか |
| text.ends_with(value) | bool | 末尾に一致するか |
| text.find(value) | int_64 | 最初の一致の開始位置。見つからなければ-1 |
| text.trim() | str | 前後の空白の書記素クラスタを除く |
| text.split(separator) | strの1次元配列 | 区切り文字列で分割。空要素も保持 |
| text.replace(old, new) | str | 重ならない一致を左からすべて置換 |

- strとcharに同じメソッドを提供する。char.trim / replaceの結果も常にstrとする。
- 代入や明示変換には既存の型変換・charの1クラスタ検査を適用し、代入先でメソッドの戻り値型を切り替えない。
- findの位置は0始まりの書記素クラスタ番号。既存の添字・lengthと単位を揃える。
- splitの受け取りは通常の`str parts[]`。新しい文字列配列型や終端要素は追加しない。
- 全メソッドは受け手を変更せず、結果を返す。加工結果を反映するには代入する。
- 変数・文字列リテラル・関数の戻り値・配列要素・modelの公開フィールド・連鎖呼び出しに対応する。
- const / ref readonlyの受け手にも使用できる。参照先を変更するメソッドとして扱わない。
- 数値・bool・配列・model等を引数の文字列へ暗黙変換しない。必要ならstr(value)を明示する。
- ref引数、名前付き引数、可変個数の引数は追加しない。個数は表のとおり固定する。
- 初版ではfindの検索開始位置、splitの最大分割回数、replaceの最大置換回数を追加しない。
- startswith / endswith / strip等の別名は設けない。既存の.lengthはプロパティのまま維持する。

## 2. 一致の定義

比較は大文字小文字を区別するUTF-8の完全一致とし、Unicode正規化は行わない。
一致範囲の開始と終了が、両方とも元の受け手の書記素境界にある場合だけ採用する。
パターンは正規表現・ワイルドカード・文字集合として解釈しない。

| 式 | 結果 | 理由 |
| --- | --- | --- |
| "QYNO".contains("qy") | false | 大文字小文字を区別 |
| "é".contains("e") | false | 結合文字を含むクラスタの途中で終わる |
| "é".contains("́") | false | クラスタの途中から始まる |
| "é".contains("é") | true | クラスタ全体とバイト列が一致 |
| "é".contains("é") | false | 正規化しないためバイト列が異なる |
| "A日😀é".find("é") | 3 | バイト位置8ではなく書記素番号3 |
| "👩🏽‍💻".contains("👩") | false | ZWJ列の一部分だけは一致にしない |

表のéはU+0065とU+0301の列、éはU+00E9を表す。

CRLFは既存仕様で1クラスタなので、"a\r\nb".contains("\n")はfalse、
contains("\r\n")はtrueとする。split / replace / starts_with / ends_withも同じ規則を使う。
混在した改行を行として処理する場合は既存のio.file.readlineを利用し、splitに改行専用の例外を作らない。
将来のsplit_linesは別APIとして扱う。

NULも文字列の内容として扱う。"a\0b".find("\0")は1。
OSのパス処理のようにNULを禁止せず、終端NULにも依存しない。

## 3. 検索と空文字列

contains / starts_with / ends_with / findは同じ一致の定義を使用する。
findは最初の一致を返し、最後の一致や一致件数は返さない。

| 式 | 結果 |
| --- | --- |
| "banana".find("ana") | 1 |
| "banana".contains("ana") | true |
| "banana".starts_with("ban") | true |
| "banana".ends_with("ana") | true |
| "banana".find("xyz") | -1 |
| "".find("x") | -1 |
| "abc".contains("") | true |
| "abc".starts_with("") | true |
| "abc".ends_with("") | true |
| "abc".find("") | 0 |
| "".contains("") | true |
| "".starts_with("") | true |
| "".ends_with("") | true |
| "".find("") | 0 |

空パターンは検索では任意の書記素境界に存在するものとする。findでは最初の境界0を返す。
検索結果が最初から決まる場合でも、受け手と引数の評価・UTF-8検証は省略しない。

## 4. trimの空白

Unicode 17.0.0のWhite_Spaceプロパティを採用し、OSのロケールやCのisspaceには依存しない。
対象は次の25コードポイントで固定する。

```text
U+0009..U+000D
U+0020
U+0085
U+00A0
U+1680
U+2000..U+200A
U+2028..U+2029
U+202F
U+205F
U+3000
```

クラスタ内のすべてのコードポイントがWhite_Spaceである場合だけ、そのクラスタを空白と判定する。
先頭・末尾から連続する空白クラスタを取り除き、内部の空白は保持する。

| 入力 | 結果 |
| --- | --- |
| "  Ken  " | "Ken" |
| "\tKen\r\n" | "Ken" |
| 全角空白＋"Ken"＋NBSP | "Ken" |
| "a  b" | "a  b" |
| 空白だけ | "" |
| "" | "" |

- U+200Bのゼロ幅スペース、U+FEFFのBOM、NUL、U+001C..U+001Fは対象外。
- 空白に結合アクセントが付いたクラスタは保持する。空白だけを除いて結合文字を切り離さない。
- 例えばU+0020＋U+0301＋"x "では、末尾の空白だけを除く。
- charの空白にtrimを呼んだ結果は空のstrになる。その結果をcharへ代入・変換すると、既存の1クラスタ制約を満たさないためエラーになる。

## 5. split

区切りは1つの文字列として完全一致させる。左から重ならない一致を採用し、区切り自体を結果へ含めない。
空要素を勝手に取り除かず、先頭・連続・末尾の区切りも保持する。

| 式 | 結果 |
| --- | --- |
| "a,b,c".split(",") | ["a", "b", "c"] |
| ",a,,b,".split(",") | ["", "a", "", "b", ""] |
| "a::b".split("::") | ["a", "b"] |
| "a::b".split(":") | ["a", "", "b"] |
| "abc".split(",") | ["abc"] |
| "".split(",") | [""] |
| ",".split(",") | ["", ""] |
| "aaa".split("aa") | ["", "a"] |
| "aaaa".split("aa") | ["", "", ""] |

- 空のseparatorは引数エラーとする。文字単位への分解として解釈しない。
- separatorの省略や、空白全般での自動分割は初版では許可しない。
- 空白の区切りも通常の完全一致。連続した空白を1つへまとめない。
- 結果は通常の可変長str配列であり、add / remove_at / clear・値コピー・ref渡しを使用できる。
- 要素やコピーを変更しても、元の文字列や別の配列の値は変化しない。
- 受け取り先が固定長配列なら、既存の配列初期化・容量・代入規則を適用する。split自身は要素数を切り詰めない。
- CSVの引用符・エスケープは解釈しない。CSV等の構造化形式は専用パーサーの対象とする。

## 6. replace

oldに一致する範囲を、元の受け手の左から重ならないように選び、すべてnewへ置き換える。
選択と次の検索位置は元の文字列を基準にし、置換済みの文字列を再検索しない。

| 式 | 結果 |
| --- | --- |
| "banana".replace("na", "NA") | "baNANA" |
| "aaa".replace("aa", "b") | "ba" |
| "a".replace("a", "aa") | "aa" |
| "abc".replace("b", "") | "ac" |
| "abc".replace("x", "y") | "abc" |
| "".replace("x", "y") | "" |

- 空のoldは引数エラー。書記素境界への挿入として解釈しない。
- 空のnewは削除として許可する。oldとnewが同じなら元と同じ値を返す。
- old / newは正規表現や置換テンプレートではない。$1等も通常の文字として扱う。
- 結果の連結箇所でクラスタが結合することがある。結果のlengthは完成した文字列から再計算する。
- 例えば"🇯,🇵".replace(",", "")の結果は"🇯🇵"で、lengthは1になる。
- 結合が起きても、既に決めた元の一致位置を変更したり、追加の置換を行ったりしない。

## 7. 評価順・値の扱い

受け手を評価し、その後に引数を左から1回ずつ評価する。
受け手と各文字列引数は、評価した時点の値を保持する。

```text
get_text().replace(get_old(), get_new())
```

呼び出し順はget_text、get_old、get_new、置換処理とする。
出力サイズの計測と生成のためにこれらの関数を呼び直さない。

引数の評価が元の変数を書き換えても、先に取得した受け手の値を使用する。
メソッド自身は元の値を変更しないが、受け手や引数の式に含まれる副作用までは取り消さない。
途中で既存のio.Errorが伝播した場合は、以降の引数やメソッド本体を実行しない。

文字列は既存の値の規則を維持する。内部で不変データを共有してもよいが、
新しいslice / view型や所有権の規則は追加しない。
splitの戻り値やreplace等の結果は、既存の値として変更・代入できる。
一時値・入力・出力の全てを、必要な間はGCのルートとして保持する。

## 8. const・型推論・エラー

- 全7メソッドは純粋な値の処理で、const式で評価できる。
- const評価、Linux / Windowsの実行、-S経由で同じ結果・境界規則を使用する。
- autoは戻り値からbool / int_64 / str / str配列を推論する。char受け手でも結果型は表のとおり固定する。
- ジェネリック関数内でも既存の具体化後の型検査を行う。
- メソッド名は予約語にしない。利用者のmodelにある同名メソッドや、同名の通常関数を維持する。
- 配列・数値等へこれらの組み込みテキスト操作を追加しない。

| 失敗 | 扱い |
| --- | --- |
| 受け手・引数の型不一致、個数違い、ref指定 | コンパイルエラー |
| 空のsplit区切り、空のreplaceのold | 定数で分かればコンパイルエラー、動的なら70 |
| 文字列の不正UTF-8 | 定数で分かればコンパイルエラー、実行時なら65 |
| 出力サイズ・要素数・作業領域の算術オーバーフロー | 定数で分かればコンパイルエラー、実行時なら70 |
| メモリ不足 | 既存のメモリ確保失敗と同じ70 |

受け手と引数はすべて評価した後、全テキストのUTF-8を受け手・引数順に検証し、
次に空パターンの契約検査、サイズ計算、結果生成を行う。
不正なUTF-8を「一致しない」「空配列」といった成功結果へ置き換えない。
動的な契約違反やデータエラーをio.Errorのcaseで捕捉する仕様には変更しない。
新しいio.ErrorCodeは追加しない。

受け手・引数に含まれる関数のI/O効果・close責任は通常どおり解析する。
メソッド自体は回復可能なOS失敗経路を導入しない。
失敗時に途中までの配列を公開したり、呼び出し先から元の文字列を変更したりしない。

## 9. 実装方針

- 型検査でstr / char受け手の組み込み操作を解決する。通常のmodelメソッドの名前解決は維持する。
- UTF-8・Unicode境界・検索・計測を純粋Cの共通処理へまとめ、コンパイラと実行時イメージで共有する。
- 既存のgrapheme_runtimeを、状態を維持して順にクラスタを取得できる内部イテレーターへ整理する。
- 既存のscan / cursorの公開内部インターフェースは互換ラッパーとして維持し、GB3〜GB13の規則を複製しない。
- Unicode 17.0.0のPropList.txtを実装時に追加し、White_Spaceの小さな範囲表を既存データ生成へ含める。通常ビルドでのダウンロードは不要にする。
- 検索はKMP等の線形時間の処理と、単調に進む書記素境界イテレーターを組み合わせる。
- 添字ごとのgrapheme_scanや、受け手の先頭からの再走査を一致ごとに繰り返さない。
- 初版の検索作業領域はパターン長に比例する範囲までとし、受け手全体の境界配列を必須にしない。
- split / replaceはサイズ計測と生成の2段階とし、入力値と検索用作業領域を再利用する。
- 純粋C処理内からOSやメモリ確保を呼ばず、コンパイラ・生成コード側が検査済みサイズで領域を用意する。
- 生成される総バイト数、配列のスロット数、ヘッダー、作業領域の加算・乗算を検査する。
- starts_with / ends_withも境界を検査する。単純なバイトprefix / suffixだけでは判定しない。
- 長い入力でも、split / replaceの走査は入力・パターン・出力の合計に比例する回数を目標とする。
- 既存のlib.length / size、文字列添字、要素置換、io.file.writeのバイト数は変更しない。

## 10. 検証項目

- 7メソッドの型・個数・値評価順、str / char、const / readonly、一時値・配列要素・modelのフィールド。
- auto・ジェネリック・const配列、利用者modelの同名メソッドとの共存。
- ASCII・日本語・結合文字・ZWJ絵文字・国旗・ハングル・インド系文字、全766件の既存境界検証。
- 検索のバイト位置と書記素位置の差、両端の境界、正規化なし、大文字小文字、CRLF、埋め込みNUL。
- 空文字列の全組み合わせ、空区切り・空oldの拒否、空newによる削除。
- 先頭・末尾・連続区切り、複数文字の区切り、重なる候補、置換結果を再検索しないこと。
- 全25種類のWhite_Space、対象外のBOM / ゼロ幅スペース / NUL / U+001C..U+001F、空白＋結合文字。
- 元の文字列・値コピー・split配列の独立性、置換後のクラスタ結合とlengthの再計算。
- get_text / get_old / get_newの評価回数と順序、引数が受け手の変数を変更する場合のスナップショット。
- 受け手や引数のI/O失敗、モジュール境界、回復経路でのfileのclose解析。
- 不正UTF-8・サイズ超過・メモリ確保失敗・GC頻発、部分結果を公開しないこと。
- 長い反復文字列と多くの区切り。厳しい実行時間閾値を合否条件にせず、走査回数と結果を検証する。
- contains(value)とfind(value)>=0の一致、replace(old,old)の恒等性、trimの冪等性、split結果のバイト再結合。
- Linux / Windows / -S / constでの一致、VS Codeの補完・引数ヒント・readonly受け手・診断。

## 11. 利用例

以下は0.27.7で実行できる。7メソッドを使う例は[examples/text/main.qy](../examples/text/main.qy)も参照。

```text
using io

int main();
	str line = "  Ken,23  "
	str fields[] = line.trim().split(",")
	str name = fields[0]
	int age = int(fields[1])
	print("{name}: {age}")

	str filename = "report.txt"
	if(filename.ends_with(".txt"));
		print("text file: {filename}")
	str message = "Hello, guest!"
	print(message.replace("guest", name))
	return 0
```
