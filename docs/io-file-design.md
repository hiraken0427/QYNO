# io.file（テキストI/O: 0.25.2、バイナリ拡張: 0.27.1）

UTF-8 のファイル操作と、明示的な close のコンパイル時検査の仕様。

バイナリI/Oの追加仕様は [0.27.1 バイナリファイル操作](binary-file-design.md) を参照。
本書のread / readline / writeはテキスト用、read_bytes / write_bytesはバイナリ用として区別する。

## 1. 対象と名前空間

io.file は import 不要の標準サブモジュールとする。
UTF-8とバイナリの通常ファイルを扱う。ディレクトリ操作、標準入出力ハンドルの取り込み、
seek / tell は後続の拡張とする。

| 記述 | 意味 |
| --- | --- |
| `io.file.open(...)` | import・using なしで使う |
| `using io.file as fs` | `fs.open(...)` のように省略する |
| `using io.file` | `open(...)`、`readline(...)` などを省略する |
| `using io` | print / input と、子名前空間 file を使える。`file.open(...)` と書く |
| `using io.file.open, io.file.close` | 指定した関数だけを省略する |
| `import io.file` | 明示的な import も許可するが、必須にはしない |

using の衝突・別名・ブロックスコープは既存の規則に従う。
io.file と同じ名前のユーザーファイルで標準モジュールを置き換えることはできない。
初めの例では、型名 file と関数名の衝突を避けて読みやすい fs の別名を推奨する。

## 2. file 型

`file` を組み込み型として追加する。OS の整数ハンドルは公開しない。

```text
file source = io.file.open("input.txt", "r")
file unopened
```

初期値のない file は未オープン状態とする。
ハンドルには、開閉状態、読み書きの権限、読み取りバッファと位置を保持する。

代入や通常の引数渡しでは同じハンドルを共有する。
ファイル内容・OS ハンドル・現在位置の複製は行わない。

```text
file first = io.file.open("input.txt")
file second = first
str text = io.file.read(first)
io.file.close(second)
```

read は両方の変数が共有する位置を進め、close は両方から見たハンドルを閉じる。
閉じたハンドルは、後で OS が同じ整数ハンドルを再利用しても復活しない。

`void consume(file source);` のような値渡しでも読み取り位置は共有する。
`ref file` は、関数内で呼び出し元の file 変数そのものを再代入する場合に使う。
単に read / write / close を呼ぶために ref は必要ない。

file の比較は同一ハンドルかどうかを表す == / != だけを許可する。
算術、大小比較、真偽値への暗黙変換、print・文字列埋め込みには使用しない。
file の配列は既存の配列規則を使い、容器はコピーするが内部のハンドルは共有する。
file 配列の初期要素および引数なし add() の初期値は未オープン状態とする。

open で取得したハンドルは、関数の正常終了へ至るすべての経路で明示的な close が必要。
確認できない場合はコンパイルエラーとする。スコープ終了だけでは閉じない。
到達可能な別名が残る間、GC はハンドルを閉じてはならない。
到達不能になったハンドルは GC で補助的に閉じるが、その実行時期は保証しない。
GC・終了処理での暗黙 close の失敗は通常の関数結果として通知しないため、
完了確認には明示的な close を使う。
開いたままの変数に別のハンドルを代入しても、以前のハンドルを自動では閉じない。
以前のハンドルも、残してある別名などから明示的に close する必要がある。

### close のコンパイル時検査

別名の代入、分岐、早期 return、break / continue、定数添字の配列要素、
呼び出した関数内での close を追跡する。close の責任は次のように扱う。

- open の結果を変数へ代入せず捨てても、そのハンドルの close は必要。
- file を返す関数は、返すハンドルの close の責任を呼び出し元へ渡す。
- ref file へ新たなハンドルを書き込む関数も、呼び出し元へその責任を渡す。
- 通常の file 引数は借用として扱い、受け取っただけでは新たな責任を作らない。
  呼び出し先が確実に閉じた場合は、呼び出し元の close として認識する。
- file 配列のコピーでハンドルの責任を複製しない。どの別名から close してもよい。
- ループ内で取得するハンドルは、次の反復までに close する。
- I/O 失敗等によるプログラムの異常終了は、正常終了経路の検査から分けて扱い、
  実行時の補助的な回収も行う。

```text
int main();
	file source = io.file.open("input.txt")
	return 0
```

上記は close がないためコンパイルエラー。別名からの close は認識する。

```text
int main();
	file source = io.file.open("input.txt")
	file alias = source
	io.file.close(alias)
	return 0
```

解析は安全側に判定する。動的な添字からの close、file を扱う再帰、
反復をまたぐ複雑な別名変更など、閉鎖を証明できないコードもエラーにする。
その場合はハンドルを個別の変数として保持し、その変数を close するか、
ファイル操作を再帰・複雑なループの外へ分離する。
解析上限は関数ごとに1023個のシンボル資源、128経路とし、超過時は関数分割を案内する。

## 3. 最初に用意する API

以下は組み込み関数のシグネチャを説明する記法。
`value` は int / float / double / bool / str / char のいずれかを表す。

| API | 戻り値・動作 |
| --- | --- |
| `open(str path, str mode = "r")` | file。指定モードで開く |
| `close(file source)` | void。ハンドルを閉じる |
| `is_open(file source)` | bool。開いているかを返す |
| `read(file source)` | str。現在位置から EOF まで読む |
| `readline(file source, ref str line)` | bool。1行読めれば true、読む行がなければ false |
| `write(file destination, value)` | int_64。全体を書き込み、書き込んだ UTF-8 バイト数を返す |
| `read_bytes(file source, int_64 count)` | unsigned int_8の1次元配列。最大countバイトを読む |
| `write_bytes(file destination, unsigned int_8 data[])` | int_64。全バイトを書き込む |
| `exists(str path)` | bool。指定先が通常ファイルとして存在するかを返す |

引数は既存の関数と同じく左から順に1回だけ評価する。
char から str への既存の変換は path / mode にも適用する。
file 以外をハンドル引数に渡すことや、readline の出力先を str 以外にすることは型エラー。
readline の出力先には、通常の ref 渡しと同じく str 変数や str 配列の要素を指定できる。

## 4. open とパス

| mode | 既存ファイル | 存在しないファイル | 権限・開始位置 |
| --- | --- | --- | --- |
| `"r"` | 内容を保持 | エラー | 読み取り専用、先頭から |
| `"w"` | open の時点で長さ0にする | 作成 | 書き込み専用 |
| `"a"` | 内容を保持 | 作成 | 書き込み専用、毎回末尾に追加 |

mode 省略時は r。文字列は完全一致で判定し、大文字や空白を自動補正しない。
0.27.1ではrb / wb / abをバイナリ専用として追加。r+ / w+ / a+などの更新モードは受け付けない。
定数で分かる不正モードはコンパイルエラー、実行時に決まる不正モードは終了コード70。
ディレクトリや通常ファイル以外を開こうとした場合は終了コード74とする。

相対パスは実行時のプロセスの作業ディレクトリを基準にする。
import の探索起点であるエントリファイルのディレクトリや -I は使用しない。
絶対パスも受け付け、区切り・大文字小文字・リンクは各 OS の通常の規則に従う。
~ や環境変数、ワイルドカードは展開せず、親ディレクトリも自動作成しない。

パスは UTF-8 とし、Windows では UTF-16 に変換して W 系 API を呼ぶ。
日本語・絵文字のパスを両 OS で扱えるようにする。
埋め込み NUL は切り詰めずに引数エラー70、不正 UTF-8 はデータエラー65とする。

新規作成時のアクセス権は OS の通常の規則に従う。
追記は OS の append 機能を使い、open 時に一度だけ末尾へ移動する実装にはしない。
複数プロセスからの write 呼び出し全体の不可分性までは保証しない。

## 5. read

現在の論理位置から EOF までの内容を UTF-8 の str として返し、位置を進める。
readline が先読みしたバッファがあれば、未消費部分から読む。
空ファイル・すでに EOF の場合は空文字列を返す。

改行・埋め込み NUL はそのまま保持する。
BOM を自動除去しない。先頭の UTF-8 BOM も U+FEFF として文字列に含める。
UTF-8 の過長形式、サロゲート、範囲外の符号位置、EOF で途切れた文字はエラー65。
UTF-8 の検証は OS の read の区切りに依存させない。
サイズ計算・メモリ確保が扱える範囲を超える場合は診断して停止する。

## 6. readline と EOF

推奨する読み方は以下。

```text
using io.file as fs

int main();
	file source = fs.open("input.txt")
	str line
	while(fs.readline(source, ref line));
		io.print(line)
	fs.close(source)
	return 0
```

LF、CRLF、単独 CR を改行として消費し、返す文字列には改行を含めない。
CRLF はバッファの境界をまたいでも1つの改行として扱う。
U+0085 / U+2028 / U+2029 は改行区切りにせず、文字列の内容として保持する。

| 現在位置からのデータ | 結果 | line |
| --- | --- | --- |
| `abc\n` | true | `"abc"` |
| `\n` | true | `""` |
| `abc` の直後が EOF | true | `"abc"` |
| 読めるバイトがなく EOF | false | 変更しない |
| `abc\n` を読み終わった後の次の呼び出し | false | 変更しない |

末尾の改行だけを理由に余分な空行を生成しない。
空行と EOF は bool で区別し、EOF はエラーにしない。
readline を文として呼んで結果を捨てた場合も EOF の扱いは変えない。
EOF 後の再呼び出しも読み取りを試みるため、後から追記されたデータを読める。

出力先 line は、1行の読み取り・UTF-8 検証が成功してから更新する。
EOF、不正データ、I/O 失敗では既存値を保持する。
失敗時にファイル位置まで元に戻す保証はしない。
read と readline は同じ位置を共有し、任意の順序で呼べる。

最初は str を直接返す readline(source) や eof(source) を追加しない。
行の有無は読み取りの結果で判定し、空行・EOF・I/O 失敗を分離する。

## 7. write

str / char はその内容、int / float / double / bool は io.print と同じ書式で書く。
文字列リテラルの `{式}` は io.print と同じように評価できるようにする。

```text
using io.file as fs

int main();
	file destination = fs.open("result.txt", "w")
	int count = 3
	fs.write(destination, "count={count}\n")
	fs.write(destination, true)
	fs.write(destination, "\n")
	fs.close(destination)
	return 0
```

write は改行を自動追加しない。`"\n"` は両 OS で LF の1バイトとして書く。
CRLF が必要なら `"\r\n"` を明示する。BOM も自動追加しない。
埋め込み NUL はデータとして書き込み、文字列終端として扱わない。
書き出す内容を先に書式化・UTF-8 検証し、データ不正ならその write は書き込みを始めない。

戻り値は文字数ではなくバイト数。例：`"日本"` は6、`"😀"` は4。
空文字列なら0を返すが、ハンドルの開閉状態・モードは検査する。
配列全体や file ハンドルは最初の write の対象にしない。

部分書き込みでは残りを繰り返し書き、全バイトの書き込み成功時だけ戻る。
OS の一時的な割り込みは、その操作の OS 規約に従って処理する。
途中で I/O が失敗した場合、すでに書いた先頭部分を巻き戻す保証はしない。
OS の write 成功はディスクへの永続化保証ではない。fsync 相当は後続の拡張とする。
初版では書き込み用の遅延バッファを持たない。

## 8. close / is_open / exists

close は二度呼んでも成功扱いにする。未オープンの file の close も何もしない。
同じハンドルを持つ全別名は閉じた状態になる。
明示的な close の OS 呼び出しが失敗した場合は74で停止する。
close を試みたハンドルは論理的には閉じ、OS ハンドルが再利用され得る操作の再試行はしない。

is_open は OS に再問い合わせせず、QYNO が管理する開閉状態を返す。
OS との通信や次の read / write の成功を保証する関数にはしない。

exists は通常ファイルが存在するとき true。
存在しない、途中の要素がディレクトリでない、指定先がディレクトリ等なら false。
シンボリックリンクは参照先を判定し、切れたリンクは false。
権限不足など、存在判定自体に失敗した場合は false に隠さず74で停止する。
exists の結果で、後続の open の成功を保証することはできない。

## 9. エラーの統一

| 分類 | 例 | 扱い |
| --- | --- | --- |
| 型・構文・close | file 以外を read、str 以外の readline 出力先、定数の不正モード、正常終了経路での close を証明できない | コンパイルエラー1 |
| 正常な終端 | EOF で readline | false、出力先保持 |
| 入力データ | 不正 UTF-8 | 実行時エラー65 |
| API の使い方 | 未オープン・閉じたハンドル、r への write、w/a への read、不正な動的モード | 実行時エラー70 |
| OS の I/O | 存在しないパスを r で開く、権限不足、容量不足、read / write / close 失敗 | 実行時エラー74 |

readline の false は EOF だけに使う。I/O 失敗を EOF に置き換えない。
呼び出し元ファイル・行・列、操作名、可能なら対象パスと OS エラー情報を診断する。
他モジュール内の呼び出しも、その実際のソース位置を表示する。

例外型や汎用 Result 型は初版で導入せず、既存の実行時診断方式を使う。
回復可能な I/O が必要になった段階で try_open 等とエラー情報の型をまとめて設計する。

## 10. 実装構成

1. TY_FILE と型検査を追加し、変数・引数・戻り値・配列・ref に対応する。
2. 組み込みの名前空間を階層化し、io.file を import 不要で登録する。
3. file を型名として保持しつつ、io.file.open / file.open / using io.file を解析できるようにする。
   型の file と名前空間の file は、後続の識別子またはドットで区別する。
4. Linux / Windows の open / read / write / close / 存在確認を共通の意味へそろえる。
5. GC が識別できるハンドル管理領域、開閉状態、共有の読み取りバッファを追加する。
6. write の書式化を stdout への直接出力から分離し、io.print と同じ結果を使う。
7. 標準入力用の端末編集を流用せず、ファイル用の UTF-8 行読み取りを実装する。
8. ファイル API は実行時に動作する関数として扱い、定数評価・式の除去・呼び出し順の変更の対象にしない。
9. 型検査後に関数間の close・所有権移動を解析し、未閉鎖の正常終了経路を拒否する。

OS ハンドルを単なる int として扱ったり、単一のグローバル読み取りバッファで
複数のファイルの位置を共有したりする実装は採用しない。

## 11. 検証対象

- r / w / a の既存・不存在、w の即時切り詰め、a の複数回追記、上限・権限エラー。
- 空ファイル、空行、末尾改行なし、末尾改行あり、LF / CRLF / CR、連続する改行。
- バッファ境界をまたぐ CRLF、UTF-8 文字、長い行、BOM、NUL、不正 UTF-8。
- read の後に readline、readline の後に read、EOF 後の呼び出し。
- readline の false 時の出力先保持、str 配列要素への ref 出力。
- 値・補間の write と io.print の書式一致、バイト数、部分書き込み・割り込み・容量不足。
- 複数ハンドルの独立した位置、別名の位置共有、close の共有、二重 close、OS ハンドル再利用。
- file の引数・戻り値・ref・配列コピー、到達可能なハンドルの GC 保持と到達不能時の回収。
- close の欠落、別名、分岐、早期 return、ループ、関数への委譲、戻り値・ref の責任移動、動的添字の保守的な拒否。
- using・別名・名前衝突、io.file と file 型の構文、複数モジュールの診断位置。
- 起動ディレクトリとエントリの場所が異なる場合、日本語・絵文字・絶対パス。
- Linux / Windows それぞれで実行。出力ファイルの実バイトも検査する。

コンパイラ実装時は個別検証の後に全体テストを1回実行する。
ZIP の展開・再ビルド・再テストは行わない。
