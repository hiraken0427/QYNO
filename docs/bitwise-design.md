# ビット演算とシフト演算の設計

現行の0.26.11では全ての64bit以下の符号付き／符号なし整数型へ拡張済み。
型ごとの範囲・演算幅・変換・入力の詳細は [新段階2の仕様](types-roadmap.md) を参照。
以下は0.26.5のint64を基本とした設計で、型と幅の拡張には上記の現行仕様を適用する。

状態: QYNO 0.26.5 で実装済み。
実行例は [examples/numbers/bitwise.qy](../examples/numbers/bitwise.qy)。
2026-10-27 の利用者方針に従い、and / or / xor を bool と int で共用する。
整数の基数表記・変換・入出力は [整数の基数表記と変換の設計](integer-bases-design.md) にまとめる。

## 1. 演算子と型による意味の切り替え

| 記法 | bool 同士 | int 同士 |
| --- | --- | --- |
| `a and b` | 論理AND。a が false なら b を評価しない | 64ビットのビットAND。両辺を評価 |
| `a or b` | 論理OR。a が true なら b を評価しない | 64ビットのビットOR。両辺を評価 |
| `a xor b` | 論理XOR。両辺を評価 | 64ビットのビットXOR。両辺を評価 |

意味と評価方法は、実行時の値や代入先でなく、左右の静的な型で確定する。
両辺とも bool または両辺とも int の場合だけ許可する。
bool と int の混在、float / double / char / str / addr / file / 配列 / モデル / interface には適用しない。
型の暗黙変換や、int の0を false と見なす規則は追加しない。

```text
12 and 10          // int: 8
12 or 10           // int: 14
12 xor 10          // int: 6
true xor false     // bool: true
true and 1         // 型エラー
1.0 or 2.0         // 型エラー
```

AND / OR / XOR の別名として band / bor / bxor は導入しない。
これらは予約語にせず、既存の識別子としての利用を維持する。

## 2. 単項演算・シフト・既存記法

| 記法 | 型 | 意味 |
| --- | --- | --- |
| `bnot a` | int → int | 64ビット全体の反転。`bnot 0` は -1 |
| `a << n` | int, int → int | 左シフト。空いた下位ビットを0で埋める |
| `a >> n` | int, int → int | 算術右シフト。空いた上位ビットを元の符号で埋める |
| `not a` / `!a` | bool → bool | 従来の論理否定 |

今回共用するのは利用者が指定した and / or / xor とする。
not / ! は bool 用の既存仕様を保ち、整数のビット反転は bnot で明示する。
`bnot true` と `not 1` は型エラー。
`^` は累乗、`|x|` は絶対値のまま維持する。
`&` / `|` / `~` によるビット演算の別記法や、廃止済みの && / || は追加しない。

## 3. 使用例

以下は利用例。

```text
using io

const int READ = 1 << 0
const int WRITE = 1 << 1
const int EXECUTE = 1 << 2

int main();
	int flags = READ or WRITE
	bool can_read = (flags and READ) != 0
	print(can_read)                    // true

	flags = flags and bnot WRITE       // WRITE を解除
	flags = flags xor EXECUTE          // EXECUTE を反転
	print(flags)                      // 5
	print(flags << 1)                 // 10
	print(flags >> 1)                 // 2

	print(0b1100 and 0b1010)           // 8
	print(0xFF and bnot 0x0F)          // 240
	print("flags={flags:0b}")         // flags=0b101
	return 0
```

ビット演算の結果を if へ直接渡す形式は認めない。条件は既存どおり bool。
比較より and / or / xor の優先順位が低いため、フラグ検査には上記の括弧が必要。

## 4. 64ビットの意味

int は既存の符号付き64ビット整数。新しい符号なし整数型は追加しない。
ビット演算では2の補数の64ビット表現を操作し、その結果を同じ int として解釈する。
表示・通常の比較・配列添字は引き続き符号付きの値。

| 値 | 対応する64ビット表現 |
| --- | --- |
| 0 | 全て0 |
| -1 | 全て1 |
| 最小値 -9223372036854775808 | 最上位ビットだけ1 |
| 最大値 9223372036854775807 | 最上位ビットだけ0、残りは1 |

小数のビット列を整数へ読み替える機能は導入しない。
必要な数値変換は既存の int(...) で明示する。シフト量も int に限定する。

## 5. 左シフト

`a << n` は64ビットのビット列を左へ n ビット移動する。
下位の空きは0、64ビットの外に出た上位ビットは破棄する。
符号付き整数の算術的な乗算や、桁あふれを検査する乗算としては扱わない。

| 式 | 結果 |
| --- | --- |
| `3 << 2` | 12 |
| `-1 << 1` | -2 |
| `1 << 63` | -9223372036854775808 |
| `0x8000000000000000 << 1` | 0 |
| `a << 0` | a |

負数にも適用でき、符号ビットの変化や上位ビットの破棄自体はエラーにしない。
for の整数更新で範囲外なら終了する既存の安全性規則は変更しない。

## 6. 右シフト

`a >> n` は算術右シフト。下位の押し出されたビットを破棄し、上位は元の符号ビットで埋める。
数学的には a / 2^n を負の無限大方向へ丸めた値に一致する。
既存の int の / は0方向へ丸めるため、負数では結果が異なる場合がある。

| 式 | 結果 |
| --- | --- |
| `12 >> 2` | 3 |
| `-4 >> 1` | -2 |
| `-3 >> 1` | -2 |
| `-3 / 2` | -1。既存の除算との違い |
| `-1 >> 63` | -1 |
| `0x8000000000000000 >> 63` | -1 |
| `0x7FFFFFFFFFFFFFFF >> 63` | 0 |
| `a >> 0` | a |

上位を常に0で埋める論理右シフト、>>>、ローテートは初版には含めない。
追加する場合は >> の意味を変えず、別の操作として設計する。

## 7. シフト量・評価順序・短絡

両方向ともシフト量は **0以上63以下**。負の量を逆方向と解釈せず、64以上を剰余にもしない。

- 右辺が定数式で範囲外なら、左辺が変数でもコンパイルエラー。
- 動的な右辺が範囲外なら、演算位置を示す実行時エラー70。
- 到達不能な分岐でも、型と不正な定数シフト量は検査する。
- 実行されない式の動的なシフト量は評価しない。

二項演算は左辺、右辺の順に各1回評価する。左辺の値は右辺の副作用より前に確定する。
シフト量の検査は両辺の値を評価した後、シフト命令の前に行う。
左辺の評価が異常終了した場合は右辺へ進まない。

int の and / or / xor と bool の xor は短絡しない。
`0 and effect()` や `-1 or effect()` でも、effect が int を返すなら実行する。
この評価を0や全ビット1による恒等式で消去してはならない。

bool の and / or は既存どおり短絡する。
`false and ((1 << get_shift()) != 0)` では get_shift を実行しない。
`0 << get_shift()` は get_shift を評価して範囲を検査する。
CPUがシフト量の下位6ビットだけを使う挙動に依存しない。

## 8. 優先順位と文法

型によって構文の優先順位を変えない。
既存の bool 式の解釈を維持し、共有する and / xor / or は比較より弱くする。

| 強い順 | 演算・構文 | 結合 |
| --- | --- | --- |
| 1 | 括弧、呼び出し、メンバー、添字、絶対値 | 既存どおり |
| 2 | ^ 累乗 | 右結合。右辺の単項演算を許す既存規則を維持 |
| 3 | 単項 + / - / bnot | 右結合 |
| 4 | `*`・`/`・`%` | 左結合 |
| 5 | + / - | 左結合 |
| 6 | << / >> | 左結合 |
| 7 | == / != / < / <= / > / >= | 既存の連鎖比較 |
| 8 | not / ! | 既存どおり |
| 9 | and | 左結合。評価方法だけ型によって切り替える |
| 10 | xor | 左結合。両辺を評価 |
| 11 | or | 左結合。評価方法だけ型によって切り替える |

| 式 | 解釈・結果 |
| --- | --- |
| `1 << 2 + 1` | `1 << (2 + 1)` → 8 |
| `8 >> 1 >> 1` | `(8 >> 1) >> 1` → 2 |
| `1 or 2 and 4` | `1 or (2 and 4)` → 1 |
| `bnot 2^3` | `bnot (2^3)` → -9 |
| `-2^2` | `-(2^2)` → -4。既存どおり |
| `(flags and MASK) != 0` | 有効なフラグ検査 |
| `flags and MASK != 0` | `flags and (MASK != 0)`。int と bool が混在して型エラー |
| `a == b xor c == d` | `(a == b) xor (c == d)` |
| `true or false xor true` | `true or (false xor true)`。右側全体を短絡 |

```text
unary   = ("+" | "-" | "bnot") unary | power
shift   = add (("<<" | ">>") add)*
compare = shift (cmp_op shift)*
not     = ("not" | "!") not | compare
and     = not ("and" not)*
xor     = and ("xor" and)*
or      = xor ("or" xor)*
expr    = or
```

and / or / xor の静的な型を決めるために、代入先から bool と int を逆算しない。
通常の数値リテラルは int、true / false は bool という従来の規則を使う。
3つ以上の bool xor は、true の個数が奇数なら true。連鎖比較としては扱わない。

## 9. const・for・代入・互換性

全ての演算を const 評価に対応させ、実行時と同じ型・64ビット結果・シフト量検査を使う。
モデルの既定値や init の既定引数に使う場合も、生成式をコンパイル時に実行しない既存規則を保つ。

範囲forの開始・終了値は、現在の加減算までの解析を shift まで拡張する。
`for(0 <= i < 1 << 3, i++);` の終了値は8。
and / or / xor を境界値に使う場合は `(MASK or OTHER)` のように括弧で囲む。
ループの比較との区切り、向き、開いた開始側、定数増分、安全な更新の規則を維持する。

<<= / >>= / and= / or= / xor= は初版に含めず、通常代入で `flags = flags or MASK` と書く。
一般の複合代入は、場所の1回評価・readonly・借用・失敗時の書き込みを別途設計してから追加する。
for の更新は既存の ++ / -- / += / -= を維持する。

新しい予約語は bnot / xor の2つ。これらを識別子やモジュールパスの一部に使うコードは変更が必要。
<< / >> は隣接する2文字を1トークンとして読む。< < / > > はシフトではない。
`a >> 1 >= 0` の >> と >= を区別し、既存の連鎖比較・累乗・絶対値を維持する。
将来のジェネリクスの閉じ山括弧は型の文脈で別途扱い、式中の >> を変更しない。

## 10. 実装方針

1. シフトの字句解析、bnot / xor の予約語、上記の固定した優先順位を追加する。
2. 構文解析では共有演算として保持し、型検査で bool / int を確定する。int の場合は専用のビット演算ノードへ変換するなど、短絡の生成経路を確実に分ける。
3. 定数式・モデル既定値の生成式・特殊化AST・file解析など、演算種別を列挙する処理を更新し、副作用や権限の検査を省略しない。
4. 定数評価は uint64_t でビット操作する。符号付きの負数の左シフトや、処理系依存の符号付き右シフトを直接使わない。
5. 64ビット列 u から int への変換は、u が INT64_MAX 以下なら通常変換し、それ以外は `-1 - (int64_t)(UINT64_MAX - u)` とするなど、処理系依存のキャストを避ける。
6. 算術右シフトの定数評価は n=0を別扱いにし、1〜63では符号なし右シフトに明示的な符号拡張を行う。64ビットシフトを発生させない。
7. コード生成は左辺の値を保持してから右辺を評価し、シフト命令の前に量を検査する。右シフトはSARを使い、内部用途のSHRを置き換えない。
8. bool の xor も両辺を評価する。int の and / or に論理短絡のコードや定数評価を流用しない。
9. Linux / Windows / -S で同じ結果と、ソース位置付きのエラー70を保証する。
10. VS Code のキーワード、式解析、演算子のハイライトを更新する。band / bor / bxor は追加しない。
