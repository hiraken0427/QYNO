# 整数の基数表記・変換・入出力の設計

現行の0.26.12ではint / unsigned intは32bit。全ての64bit以下の符号付き／符号なし整数型にも対応する。
型ごとの範囲・演算幅・変換・入力の詳細は [新段階2・3の仕様](types-roadmap.md) を参照。
以下は0.26.5のint64を基本とした設計で、型と幅の拡張には上記の現行仕様を適用する。

状態: QYNO 0.26.5 で実装済み。
[ビット演算とシフト演算](bitwise-design.md) と同時に実装。
リテラル、str / int の変換、print / input の埋め込みで同じ基数・値の規則を使う。
実行例は [examples/numbers/bases.qy](../examples/numbers/bases.qy)。

## 1. 表記を揃える

| 基数 | リテラル | print の埋め込み | input の入力先 |
| --- | --- | --- | --- |
| 2進 | `0b1111` | `{n:0b}` | `{n:0b}` |
| 8進 | `0o17` | `{n:0o}` | `{n:0o}` |
| 10進 | `15` / `0d15` | `{n}` / `{n:0d}` | `{n}` / `{n:0d}` |
| 16進 | `0xF` | `{n:0x}` | `{n:0x}` |

値は全て同じ int の15。基数は別の型や、int に保持され続ける属性にはしない。
数値を別の基数で見たい場合は、表示または文字列変換時に基数を指定する。
基数指定を省略した数値表記・出力は10進数とする。先頭の0だけで8進数にしない。

```text
int a = 15
int b = 0b1111
int c = 0o17
int d = 0d15
int e = 0xF

io.print(a == b and b == c and c == d and d == e) // true
io.print("{a:0b}, {a:0o}, {a:0d}, {a:0x}")       // 0b1111, 0o17, 0d15, 0xf
io.print(a)                                    // 15
```

## 2. ソースリテラル

- 接頭辞は 0b / 0B、0o / 0O、0d / 0D、0x / 0X。16進のa〜fも大小文字を区別しない。
- 接頭辞の直後に1桁以上の数字が必要。数字はその基数で有効なものに限る。
- `_`、数値型サフィックス、浮動小数点の基数指定は初版には追加しない。
- 接頭辞なしは10進数。`010` は10、`0o10` は8。
- 不正な桁や直後の英字を、別の有効なトークンへ分割して受け入れない。

10進数は、接頭辞の有無にかかわらず符号付き int の値を表す。
正の値は最大9223372036854775807。最小値は `-9223372036854775808` / `-0d9223372036854775808` と書ける。
最小値を扱うため、負号の直後の10進整数リテラルに限り、絶対値9223372036854775808を受け付ける。
この大きさを正の式、単項 + の対象、単独のリテラルとして使う場合はエラー。

2進・8進・16進のリテラルは、0〜2^64-1のビット列を受け付け、2の補数の int として解釈する。
先頭の0は値を変えず、64ビットに収まるかは桁数だけでなく値で検査する。
符号なし整数型や、正の2^64-1という int の値を導入する意味ではない。

| 表記 | int の値 |
| --- | --- |
| `0x7FFFFFFFFFFFFFFF` | 9223372036854775807 |
| `0x8000000000000000` | -9223372036854775808 |
| `0xFFFFFFFFFFFFFFFF` | -1 |
| `0o1000000000000000000000` | -9223372036854775808 |
| `0o1777777777777777777777` | -1 |
| `0d18446744073709551615` | 範囲外エラー。10進はビット列の形式ではない |

非10進のリテラルに付く + / - は、その int への通常の単項演算。
`-0xFF` は-255、`-0xFFFFFFFFFFFFFFFF` は1となる。
最小値の符号反転は既存の64ビットの規則に従い最小値になる。
この符号規則は後述の int(str) と input の整数読み取りでも揃える。

`0b102`、`0o8`、`0d1A`、`0xGG`、接頭辞だけの値、64ビットを超える非10進の値はコンパイルエラー。

## 3. print と file.write の埋め込み

整数の出力欄を `{式:0b}` / `{式:0o}` / `{式:0d}` / `{式:0x}` と書く。
指定は int の式に限定する。式は記述位置で1回評価し、その値を書式化する。

```text
int n = 255
io.print("bin={n:0b}, oct={n:0o}, dec={n:0d}, hex={n:0x}")
// bin=0b11111111, oct=0o377, dec=0d255, hex=0xff

io.print("next={n + 1:0x}") // next=0x100
io.print("{0b1111:0x}")    // 0xf
```

指定した書式は接頭辞を付けて出力する。接頭辞と16進の数字は小文字に正規化する。
正の値の余分な先頭0は付けず、0は0b0 / 0o0 / 0d0 / 0x0とする。
書式指定を省略した `{n}` と `print(n)` は従来どおり接頭辞なしの符号付き10進数。
`{n:0d}` の負号は接頭辞より前に置く。-15なら `-0d15`。

2進・8進・16進は64ビットの表現を出力する。負数には負号を付けず、2の補数の表現とする。

```text
int n = -1
io.print("{n} {n:0d} {n:0x}") // -1 -0d1 0xffffffffffffffff
```

この出力を同じ基数の input / int(str) で読めば同じ int に戻る。
幅・0埋め・桁区切り・大文字出力・一般の数値書式は後続とし、初版は上記4指定だけに限定する。
`{n:x}` や `{n:16}`、動的な `{n:base}` は認めない。動的な基数は str(n, base) を使う。
float / double / bool / char / str / 配列 / モデルへの基数指定は型エラー。

print の本文と end=、同じ書式化を利用する io.file.write に対応する。
従来の名前空間・using・別名にも同じ仕様を適用する。

```text
io.print("{n:0x}", end=" [{n:0d}]\n")
io.file.write(destination, "value={n:0x}\n")
```

通常の文字列リテラル全体を補間可能にする変更は行わない。
保存したい文字列は次節の str を使う。既存の `\{` / `\}` によるエスケープを維持する。

## 4. str と int による変換

既存の型変換に、整数の文字列化と文字列からの整数変換を追加する。
以下のシグネチャは組み込みAPIの説明であり、通常の関数へ既定引数や名前付き引数を追加するものではない。

```text
str(int value, int base=10, bool prefix=false) -> str
int(str text, int base=0) -> int
```

既存の str(str / char)、int(int / float / double) の意味は維持する。
base / prefix は今回の整数変換形式にだけ指定できる。
str(float / bool / モデル) など、他の型の文字列化は今回追加しない。

```text
str a = str(255, base=2)                 // "11111111"
str b = str(255, base=8, prefix=true)    // "0o377"
str c = str(255)                         // "255"
str d = str(255, 16, true)               // "0xff"
int n = int("0b11111111")               // 255。接頭辞から判定
int m = int("ff", base=16)              // 255。接頭辞なしを16進として読む
str converted = str(int("0o377"), 16, true) // "0xff"
io.print(converted)
```

str の base は2 / 8 / 10 / 16。prefix=falseでは接頭辞を省き、trueでは付ける。
負数の非10進表示は接頭辞なしでも2の補数とする。`str(-1, 16)` は `"ffffffffffffffff"`。
負の10進数は prefix=falseなら `"-15"`、trueなら `"-0d15"` の形。

int の base は0 / 2 / 8 / 10 / 16。0は自動判定であり、8進数を意味しない。
省略時も0。接頭辞があればそれに従い、なければ10進数とする。
固定のbaseでは、接頭辞なしの数字をその基数で読み、接頭辞があれば一致を要求する。

```text
int("10")             // 10
int("010")            // 10
int("0o10")           // 8
int("10", 16)         // 16
int("0x10", 16)       // 16
int("0b10", 16)       // 基数不一致のエラー
int("0x0b10", 16)     // 2832。0b10を16進の桁として扱いたい場合
```

認識可能な接頭辞は、固定baseでも先に接頭辞として扱う。
たとえば16進の欄に0b10と書かれた場合、16進の2832として黙って読み替えない。
接頭辞なしの表記を文字列化するstrの結果には、0そのもの以外に先頭0を付けないため、この曖昧さは生じない。

位置引数と base= / prefix= を許可する。位置引数は名前付き引数より先に書く。
重複・未知名・必須値の欠如を診断し、明示引数は記述順に1回評価してからオプションを検査する。
baseはint、prefixはboolに限定し、固定した不正なbaseはコンパイルエラー、動的な不正baseは実行時エラー70。

const式にも対応する。定数で確定する変換の不正はコンパイルエラー。
動的なint(str)の不正データ・桁あふれは実行時エラー65。従来のint(小数)の範囲外エラー70は維持する。

## 5. 整数文字列を読む共通規則

int(str)、input の int、後述の基数指定欄は同じ変換エンジンを利用する。

1. 文字列の外側のASCII空白を、従来のint入力と同じ規則で除く。
2. 任意の + / - を1つ読み、その後の接頭辞と数字を読む。符号・接頭辞・数字の間に空白は許可しない。
3. 自動判定または固定baseを決定する。異なる接頭辞は不一致として失敗する。
4. 文字列全体を消費し、有効な数字が1桁以上あることと範囲を検査する。
5. 10進なら符号付きintの範囲で読み取る。非10進なら64ビット列をintに解釈し、付いていた符号を単項演算として適用する。

非10進で負号付きの巨大なビット列を読む場合もソースと同じ規則。
`int("-0xffffffffffffffff")` は1であり、負の2^64-1を格納する意味ではない。
通常の負数は `-255` / `-0d255` として扱え、非10進では `-0xff` でも-255になる。

空文字列、符号だけ、接頭辞だけ、不正な数字、小数・指数表記、数字中の空白、埋め込みNUL、範囲外は失敗。
Unicode数字・全角数字・ロケール依存の区切りは追加しない。
先頭0だけでは8進数にならない。10進の範囲を超えた入力を非10進のビット列として自動救済しない。

## 6. input の基数指定と自動判定

int の入力先で、`{入力先:0b}` / `{入力先:0o}` / `{入力先:0d}` / `{入力先:0x}` を使う。
変数・refのvalue・モデルフィールド・多次元配列要素など、既存の入力先を維持する。
書式欄は表示する式ではなく、読み込み先と読み取り規則を指定する。

```text
using io

int main();
	int n
	if(io.input("hex> {n:0x}"));
		io.print("{n:0b} / {n:0o} / {n:0d} / {n:0x}")
	else;
		io.print("16進数を入力してください")
	return 0
```

この例は `ff` / `0xff` / `0XFF` を受け付け、255を格納する。
`255` と入力すれば16進の0x255、つまり597として読む。
10進の255を読みたい場合は `{n:0d}` または指定なしの `{n}` を使う。

| 入力欄 | 入力例 | 結果 |
| --- | --- | --- |
| `{n:0b}` | 1111 / 0b1111 | 15 |
| `{n:0o}` | 17 / 0o17 | 15 |
| `{n:0d}` | 15 / 0d15 | 15 |
| `{n:0x}` | f / 0xf | 15 |
| `{n}` | 15 / 0b1111 / 0o17 / 0d15 / 0xf | 自動判定して15 |
| `{n}` | 010 | 10 |
| `{n:0x}` | 0b1111 | 基数不一致で失敗 |

形式を省略したintのinput(n)、input("{n}")、int n=input() も接頭辞の自動判定に対応する。
接頭辞のない値が10進である既存仕様は維持し、これまで不正だった明示接頭辞の入力を新たに受け付ける。
他の型の入力書式は変更しない。int以外に :0b / :0o / :0d / :0x を指定したらコンパイルエラー。

直接入力・値入力にbase=引数を増やす機能は今回追加しない。
固定baseで直接1値を得たい場合は、入力欄を使うか、次のように文字列入力と変換を組み合わせられる。

```text
int n = int(io.input("hex> "), base=16)
io.print("hex={n:0x}, decimal={n}")
```

`input("0x{n}")` の先頭の0xは単なるプロンプトであり、基数指定にはならない。
基数を固定したい場合は入力先の書式欄に明示する。

## 7. 複数入力・失敗・安全性

既存の複数入力の区切りと、失敗時に全ての変数を保持する規則を維持する。

```text
int binary = 7
int hex = 8
bool ok = io.input("bin, hex> {binary:0b}, {hex:0x}")
```

入力 `1010, ff` なら ok=true、binary=10、hex=255。
入力 `1010, gg` なら ok=false、binary=7、hex=8のまま。

- 全ての入力先の評価・添字の確定と、最後の更新前の参照先再検査を既存規則どおり行う。
- 先に読んだ入力値によって後の添字を変更しない。readonly・const・ループ変数などの制約も維持する。
- 不正な基数・形式の指定はコンパイル時に拒否し、入力を開始しない。
- データ不正・基数不一致・桁あふれ・EOFは、boolとして使う入力ではfalse。文としての失敗・値入力の失敗は既存どおりエラー65。
- 式や入力先の評価そのものの副作用は、入力失敗で巻き戻さない。変数への入力値の反映だけを全体成功後に行う。
- 区切り・末尾の枠・CRLF・端末編集・プロンプトの扱いは維持する。入力欄同士の間には既存どおり区切りが必要。

input(prompt=...) は引き続き表示専用の値を受け取る。入力先の埋め込みには切り替えない。
`input(prompt=str(previous, 16, true))` のような表示も可能だが、プロンプトの値から入力基数を推測しない。

## 8. 全体の変換例

```text
using io

int main();
	int n
	if(io.input("number> {n}"));
		io.print("binary  : {n:0b}")
		io.print("octal   : {n:0o}")
		io.print("decimal : {n}")
		io.print("explicit: {n:0d}")
		io.print("hex     : {n:0x}")
		str saved = str(n, base=16, prefix=true)
		int restored = int(saved)
		io.print(restored == n)
	return 0
```

15、0b1111、0o17、0d15、0xf のどれを入力しても同じ結果。
この相互変換では int 自体の値・型を変えず、入力時の解釈と出力時の表現だけを切り替える。

## 9. 埋め込み構文と実装方針

書式指定は波括弧の最上位のコロンで式と分離する。式内の文字列や括弧・添字・入れ子のコロンとは区別する。
式の前後とコロン前後の空白は許可し、書式名の中の空白は認めない。
書式名は小文字の0b / 0o / 0d / 0xに限定する。入力データやソースの接頭辞の大小文字とは別の規則。
未知の書式、空の書式、複数の書式はコンパイルエラー。
元のソース列を保持し、不正な指定と不正な入力先を区別して診断する。

1. 字句解析に4接頭辞と桁の検証を追加し、10進最小値の特例を含め、符号付きオーバーフローを発生させずに読む。
2. 変換基盤に自動base・固定base・接頭辞・符号・数字全消費・範囲検査をまとめる。64ビットの非10進と符号付き10進を区別する。
3. 出力基盤に4基数の桁生成と接頭辞を追加する。int最小値の絶対値を符号付きで計算せず、出力の長さ・割当範囲も検査する。
4. str / int の既存の数値・文字変換を型で分岐し、base / prefix の名前付き引数は組み込みの該当形式に限定する。通常の関数呼び出しの文法を拡張しない。
5. 定数評価とランタイムで共通の値の規則を使い、ソースリテラル・int(str)・input の意味を一致させる。
6. 出力の埋め込みに基数メタデータを保持し、通常の式の型や演算結果へ基数属性を付けない。file.write と end= へも伝える。
7. input の各InputFieldへ基数を保持し、場所の評価・仮入力・最後の一括更新の流れを保ったまま整数解析だけを切り替える。
8. const・モデルの既定値・interface の特殊化・file解析・GCで、追加メタデータとノードを失わないようにする。formattingを純粋な変換として扱い、inputを定数化しない。
9. Linux / Windows のUTF-8・端末入力・エラー位置・終了コードを揃える。埋め込みNULを文字列末尾と誤認しない。
10. VS Codeのリテラル・書式指定・演算子のハイライト、埋め込み内の変数・添字補完、int / str の引数ヒントを更新する。

## 10. 受け入れ条件

専用テストは tests/integer_bases_test.py の33件。make test-integer-bases と全体テストに含める。

- 4基数、大小文字の接頭辞、先頭0、0、最大最小値、符号付き値、非10進の全ビット1。
- 正負の10進境界、非10進の64ビット境界を越えた値、不正な桁、接頭辞だけ、後続文字、NULを拒否。
- `str(int(s), base, prefix)` と `int(str(n, base, true))` の相互変換を全基数と境界値・複数の値で確認。
- str(n, base, false) の非10進表記は同じ固定baseで読むと元のnに戻る。自動baseで読む場合は接頭辞が必要なことも確認。
- int(str) の自動・固定base、異なる接頭辞の拒否、符号規則とソースの一致、外側の空白と全体消費。
- base / prefix の型・既定値・位置/名前付き引数・重複/未知名・記述順の1回評価、定数/動的な不正base。
- constと実行時の一致、モデル既定値と生成式、interface特殊化を経由した型と書式の維持。
- print / end= / file.write、式の1回評価、通常の10進出力、0dの負号位置と非10進の負数。
- input の自動判定と固定base、接頭辞あり/なし、複数欄・区切り・枠・EOF・失敗時の全体保持。
- モデルフィールド・配列要素・ref・readonly・const・参照先再検査と、既存の他の型の入力。
- リテラルと書式が混在する補間、エスケープ、式内のコロンを含む文字列と書式指定の区別。
- Linux / Windows、アセンブリ、GC多発、未定義動作検査、実際のVS Codeでの補完と表示。
