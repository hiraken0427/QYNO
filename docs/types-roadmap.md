dev にコミットし、hiraken0427 名義で **1 回 push したら次の指示を待つ**。

## auto の共通仕様（旧段階1から）

関数・メソッド・init の本体で、初期値付きのローカル宣言に使用できる。

```text
int main();
	auto count = 3
	auto ratio = 0.5
	auto title = "QYNO"
	auto enabled = true
	auto values = [[1, 2], [3, 4]]
	const auto LIMIT = 10
	print("{count} {ratio} {title} {enabled} {values} {LIMIT}")
	return 0
```

- auto は実行時の型ではなく、初期値の型を宣言に採用する指定。代入後に型は変わらない。
- 旧段階1〜新段階2のintは64bit。新段階3（0.26.12）からintはint_32の別名となる。char はUnicodeスカラー値1個のまま。
- 小数リテラルは double、文字列リテラルは str。float / char は変換関数や既存の型付き値から推論できる。
- 配列は既存の要素型・次元数の推論を使用する。`auto values = [1, 2]` と書き、名前の後に次元は指定しない。推論した配列に固定上限は付かない。
- 空配列や `{x=1}` のように型の文脈が必要な初期化子だけでは推論できない。モデルは型付き変数や戻り値から推論する。
- 配列・モデルは既存の独立したコピー、file は既存の共有ハンドルとして扱う。readonly と明示 close の検査も維持する。
- `input()` の戻り値をそのまま推論すると str。`input(target)` は bool。入力先の型を後から実行時に推測しない。
- 初期値を省略できない。自己参照と同じスコープの重複宣言は禁止する。旧段階2からは、明示的な内側の宣言で外側のローカル変数を隠すことができる。
- 旧段階3からはファイル先頭の const、旧段階4からは関数の戻り値にも対応する。新段階1からは関数引数にも対応する。フィールド、ローカル ref 宣言、for ヘッダーには auto を導入しない。
- addr / none、戻り値のない式、interface の所有値を推論して格納することはできない。
- auto は予約語になる。従来 auto を識別子にしていたコードは名前の変更が必要。

VS Code は auto のハイライト、名前補完・定義参照に対応する。
拡張はコンパイラとは独立した構文解析を使うため、ホバーには宣言どおり auto を表示し、
この段階では推論された型に基づくメンバー補完は行わない。

## 旧段階2の実装仕様（0.26.7）

未宣言の単純な名前への `=` は、現在のブロックに変数を宣言する。
初期値は auto と同じ規則で推論し、配列・モデル・file の扱いも同じ。

```text
int main();
	count = 3
	if(true);
		count = count + 1       // 外側の変数へ代入
		auto count = str(count) // 初期値では外側を参照し、別の変数を宣言
		print(count + "!")
	print(count)               // 外側の int、値は4
	return 0
```

- 既存のローカル変数・引数への `=` は代入。内側のブロックでも同じ参照先と型を維持する。
- 同名の別変数を作る場合は、内側で型または auto を明示する。const / ref の明示宣言でも同じスコープ規則を使う。
- 初期値は、新しい変数を登録する前のスコープで解釈する。外側に同名の変数があれば初期値から参照できる。
- 同じブロックでの二重宣言、および関数・メソッド本体直下での引数と同名の宣言はエラー。
- this はモデルの暗黙引数として維持し、内側の宣言でも隠せない。
- 分岐・ループ内の新規変数は、そのブロック内だけで有効。兄弟ブロックに同じ名前の別変数を宣言できる。
- `+=` / `-=` / `++` / `--`、添字・フィールド・value・addr への更新は新規宣言にならない。元の変数が必要。
- 定数、関数、型、import / using の名前を型名省略の宣言で置き換えることはできない。明示的な宣言のモジュール名衝突規則も維持する。
- ファイル先頭の代入は未対応。`const NAME = ...`・ファイル先頭の `const auto NAME = ...` は旧段階3で追加する。
- for ヘッダーは従来どおり専用のループ変数を宣言する。外側と同名にする場合は `for(0 <= int i < 3, i++);` のように型を明示する。
- ref の寿命検査・readonly・interface の所有制限・file の明示 close の検査は、名前や宣言方法を変えても維持する。

警告は、今回導入した **型名を省略した宣言** が読み取り・参照されない場合に出す。
単純な再代入だけでは使用とみなさない。複合更新、入力先、ref 引数、addr 参照、埋め込み文字列中の参照は使用とみなす。
明示的な型付き宣言・auto・const の既存の警告動作は変更しない。
警告はソース位置を示すが、コンパイルは成功し、初期値の副作用も実行する。
警告は制御フロー上の実行可能性を判定するものではない。

未使用の名前と、宣言位置で見えていたローカル変数・引数の名前が1文字の挿入・削除・置換・隣接入れ替えで一致する場合、候補を示す。
誤候補を減らすため双方3文字以上とし、変数名を自動修正しない。interface の具体化でも元の宣言ごとに1回だけ警告する。

VS Code は型名を省略したローカルの宣言・代入を区別し、ブロックと宣言位置に従って名前補完・定義参照を行う。
推論した具体型の表示は引き続き行わず、宣言の型を auto と表示する。

## 旧段階3の実装仕様（0.26.8）

型推論付き定数を、ファイル先頭にも宣言できる。`const NAME = 初期値` は `const auto NAME = 初期値` と同じ意味で、ローカルにも使える。

```text
const LIMIT = BASE + 1
const auto BASE = 3
const LABEL = "QYNO"

int main();
	int values[LIMIT]
	print("{LABEL}: {values.length}")
	return 0
```

- 型は初期値から決め、値はコンパイル時に計算する。通常の関数・メソッド・input・ファイル操作を定数式として実行することはない。
- ファイル先頭の定数は、宣言より前の関数・定数から参照できる。型を明示した従来の定数と混在できる。
- import、名前空間の修飾名、using、モジュール別名を通して型と値を解決する。名前は各モジュールのスコープに属する。
- 型推論に必要な定数を先に検査・評価し、結果を再利用する。推論または評価が同じ定数へ戻る循環はエラー。
- 未解決の定数を同時に調べる深さは256段までとし、深すぎる場合はコンパイルエラーにする。
- 配列は初期値から要素型・次元数を推論する。空配列だけでは型を決められないが、型を明示した空配列の定数からの推論は可能。
- モデルは型付きの定数や `Point()` のような構築式から推論できる。`{x=3}` だけではモデルの型を決められない。
- init を含むモデルの定数化、file を含むモデルの定数化、private / readonly / interface の制約は維持する。
- 配列上限、モデルのフィールド既定値、init の既定引数でも推論付き定数を使用できる。モデル既定値も依存する定数に合わせて必要な順で検査する。
- 定数自体とその要素・フィールドへの代入、変更可能な ref 渡し、addr の取得は禁止。通常の値渡し・ローカルへの独立したコピー・readonly の借用は可能。
- ファイル先頭の変更可能な変数は導入しない。戻り値の推論は旧段階4、引数の推論は新段階1で追加する。
- ファイル先頭の定数とローカルの const は、旧段階2の未使用変数警告の対象にしない。

VS Code は両方の定数宣言を認識し、前方参照・モジュール経由の補完・定義参照・ホバー・アウトラインに対応する。
型表示は `const auto NAME` とし、この段階でもコンパイラの推論結果を表示するものではない。

## 旧段階4の実装仕様（0.26.9）

引数型を明示した関数の戻り値を推論できる。先頭の auto は省略可能。

```text
auto square(int x) = x^2
twice(int x) = x * 2

choose(bool first);
	if(first);
		return 3
	return 2.5

int main();
	print("{square(3)} {twice(4)} {choose(true)}")
	return 0
```

- 数式形式は式の型、ブロック形式は全 return の型から決定する。型を省略した引数の扱いは新段階1の仕様に従う。
- 呼び出し元の代入先にも依存しない。`read() = input()` は str を返し、数値入力が必要なら `read() = int(input())` などと明示する。
- 関数の前方参照、import / using / 別名、モデルのメソッドに対応する。メソッドの public / private / readonly と this の規則を維持する。
- 本体は必要な順で1回だけ型検査する。呼び出し元のローカル変数・借用の権限・生成用一時変数を、別の関数の検査に引き継がない。

| return の型の組み合わせ | 推論結果 |
| --- | --- |
| すべて同じ型 | その型 |
| int / float / double | 既存の数値昇格に合わせて最も広い型 |
| char / str | str |
| 同じ要素型・次元数の配列 | その配列型 |
| 同じモデル型 | そのモデル型 |
| return なし、または値なしの return のみ | void |
| 値ありと値なしの混在、bool と int、異なるモデル・配列型など | コンパイルエラー |

- 先に出た return に合わせて他の式を丸めることはしない。到達しない return も型検査・型の統一の対象にする。
- 値を返す関数では、最後まで進めるすべての道筋で return が必要。従来の while(true) / break の判定規則を維持する。
- 数式形式で void の式を返すことはできない。値のない処理はブロック形式で記述する。
- 空配列や `{x=3}` だけでは型を推論できない。型付きローカル値を返すか、従来の型付き戻り値を使う。
- 配列は次元数まで推論するため、`auto make()[]` のような戻り値の次元指定は行わない。推論された配列の各次元に固定上限は付かない。
- 配列とモデルの戻り値は独立したコピー。file と file を含む値の共有ハンドル・明示 close の責任は従来どおり検査する。
- readonly の file を変更可能な戻り値へコピーしたり、interface の借用を所有値として返したり、addr を新たな戻り値型として公開したりはできない。
- main は `int main();`、init は void / bool、interface の契約は明示した戻り値型を使用する。
- interface を実装するモデルのメソッドには推論を使えるが、推論結果・引数・readonly・配列上限が契約に一致する必要がある。
- 戻り値型の依存が循環したら、関係する関数の戻り値型の明示を求める。推論を途中の return だけで仮確定しない。
- 同時に検査する関数本体の依存の深さは256段まで。これは型検査の上限であり、実行時の再帰回数の制限ではない。

相互再帰では、片方の型注釈によって戻り値型の依存を切ることができる。

```text
even(int n);
	if(n == 0);
		return true
	return odd(n - 1)

bool odd(int n);
	if(n == 0);
		return false
	return even(n - 1)
```

通常関数を定数式として評価する機能は追加しない。型名を省略した引数は新段階1で追加する。
VS Code は両方の定義形式について補完・定義参照・ホバー・引数ヒント・アウトラインに対応し、
戻り値の表示は auto とする。具体的な推論結果を表示する型検査器ではない。

## 新段階1の実装仕様（旧段階5、0.26.10）

関数とモデルの通常メソッドで、引数の型を省略または auto と書ける。
呼び出し時の引数の具体型ごとに、型検査済みの関数を生成して再利用する。

```text
square(x) = x^2
auto twice(auto x) = x * 2
int integer_square(x) = x^2

increase(ref x);
	x++

int main();
	print(square(3))       // int
	print(square(1.5))     // double
	print(twice(2.5))      // double
	n = 3
	increase(ref n)
	print(integer_square(n))
	return 0
```

- 引数は位置ごとに独立して推論する。明示した型の引数とも混在できる。
- 同じ元関数と推論引数の型の組み合わせは再利用する。実引数の値や配列の長さは具体化のキーに含めない。
- `int f(x)` の戻り値制約から x を int に固定しない。double を渡して戻り値も double になれば、int へ暗黙変換できないためエラーになる。
- 戻り値を省略した関数は、各具体化ごとに旧段階4の規則で戻り値を決める。
- 関数本体の元の構文木・ローカル変数・定数・配列上限・入力用一時変数を具体化ごとに複製する。別の型の検査結果や演算子の変換を共有しない。
- 値引数は従来のコピー、ref は同じ場所への参照、ref readonly は読み取り専用の借用とする。呼び出し側の ref の有無を検査する。
- 配列は要素型と次元数を含む型全体を推論する。`f(x[])` ではなく `f(x)`、全体のrefは `f(ref x)` と書く。
- const の配列・モデルを ref readonly 引数に渡す場合の一時コピーも、従来どおり呼び出し元に確保する。
- addr / void / interface の所有値を新たな推論引数型にはしない。型文脈のない空配列やモデル初期化子だけからも推論できない。
- モデルの private / readonly の権限は関数の定義位置で決める。具体化を依頼した呼び出し元の権限を引き継がない。
- interface の契約、interface を実装するメソッド、init の引数型は明示する。通常のジェネリック関数では、型を明示した ref interface と別の推論引数を混在できる。
- 定義は構文と宣言名の規則を検査する。本体の型検査・close 検査は実際に具体化した型について行い、未使用テンプレートは実行ファイルに出力しない。
- 具体化した本体の全分岐を型検査する。実行時の if で型ごとの不正な操作を隠せる仕組みにはしない。
- 再帰で戻り値の推論が循環する場合は型を明示する。明示した戻り値を持つ同じ型の再帰は、作成中の具体化を再利用できる。
- プログラム全体の具体化数は4096件まで。既存の関数検査の依存深さ256段・配列の最大次元数も適用し、型が増殖する再帰を制限する。
- file を値渡ししても共有ハンドルのまま扱い、正常終了する経路での明示 close を検査する。readonly の file をコピー・変更する制限も維持する。
- 引数の実行時評価順は従来どおり左から右で、具体化のために実引数を実行したり、重複評価したりしない。
- 通常関数を定数式として実行する機能、関数オーバーロード、実行時に変わる動的型は導入しない。
- 未使用の型名省略ローカルの警告は、使用された元テンプレートの宣言ごとに1回だけ出す。

VS Code は省略した引数を auto と表示し、名前補完・定義参照・ホバー・引数ヒントに使用する。
具体的な型ごとの生成済み関数をエディターが別々に表示するものではない。

## 新段階2の実装仕様（旧段階6・7、0.26.11）

- `int_8` / `int_16` / `int_32` / `int_64` と、その前に `unsigned` を置く型を追加する。
- `int` は引き続き符号付き64bitで `int_64` と同じ型。`unsigned int` は `unsigned int_64` と同じ型。32bitへの別名変更は新段階3で行う。
- 符号付きNbitの範囲は -2^(N-1)〜2^(N-1)-1、符号なしは0〜2^N-1。内部の変数・配列要素・引数スロットは8バイトを維持する。bit数は値と演算の幅を表し、詰めたメモリ配置を保証しない。
- 全ての整数型を変数・定数・モデルのフィールド・配列・引数・戻り値・ref / readonly・addrの指す先・auto / ジェネリックの具体型に使用できる。
- 暗黙変換は元の型の全範囲を表現できる整数型への拡大、または対象型に収まる整数定数に限る。負数を符号なしへ暗黙変換したり、狭い型への代入で上位bitを捨てたりしない。
- `int_8(x)` / `unsigned int_64(x)` などの明示変換にも範囲検査を行う。数値とstrから変換でき、strには `base=0/2/8/10/16` を指定できる。小数は対象範囲内でのみ0方向へ切り捨てる。静的に分かる範囲外・NaN・無限大はコンパイルエラー、それ以外は実行時エラー70。文字列変換の失敗は65。
- 10進整数リテラルは正の2^64-1まで受け付ける。2^63-1以下は従来のint、それより大きいものはunsigned int_64へ推論する。負の最小値 `-9223372036854775808` は従来どおりint。
- 非10進リテラル単独の従来のint64ビット列解釈は維持する。unsignedの文脈では `unsigned int_64 max=0xffffffffffffffff` も最大値を表す。狭い型に収まらないbitは切り捨てない。`int_8(255)` は範囲外、`int_8("ff",base=16)` は8bitのビット列として-1になる。
- 整数同士の演算・比較は両方の型を表現できる共通型へ拡大する。例: int_8とunsigned int_8はint_16。int_64とunsigned int_64の一般的な組み合わせは、安全な共通型がないため明示変換を要求する。
- 通常のintリテラルやint定数がもう片方の型に収まる場合、その型に合わせる。明示した異なる幅の型同士は共通型へ拡大する。配列要素・複数returnの推論も整数の共通型を使用する。
- 加減算・乗算・累乗・単項マイナスは演算結果型のbit幅で折り返す。従来のint64と同じ規則を狭い型へ適用する。除算の0と符号付き最小値/-1は診断し、最小値%-1は0。
- `and` / `or` / `xor` は整数なら両辺を評価してビット演算、boolなら既存の論理演算。boolと整数は混在しない。`bnot` とシフトは結果のbit幅を保ち、符号付きの `>>` は算術、符号なしは論理シフト。シフト量は0〜左辺のbit幅-1。
- `^` の指数とround系の桁数は内部のint64で扱い、unsigned int_64の2^63以上の値を渡す場合は範囲外とする。
- mathのabs・sqrt・round系は整数型を受け付ける。round系は整数の商・余りで計算し、対象型に収まらない丸め結果を診断する。int64以上の値を一度doubleにして丸めない。
- print・file.write・strの基数指定は全整数型に対応する。10進は符号の有無に従い、非10進はその型のbit幅で表示する。`int_8(-1)` の16進表示はff。
- inputの直接指定・補間・値形式で入力先のbit幅と符号を検査する。非10進の入力は対象の幅のビット列として読む。unsignedの負号は拒否する。失敗をboolで受け取る形式では、全ての入力先を変更しない。
- 添字・remove_atは全整数型を受け付け、内部のint64位置へ変換できるか検査する。forのループ変数にも全整数型を指定でき、その型の上限・下限を越える更新では折り返さずループを終了する。
- VS Codeの型名ハイライト・補完、unsignedを含む変数・フィールド・引数・戻り値の解析、変換の引数ヒントに対応する。

```text
using io

increase(ref x);
	x++

int main();
	int_8 small = 127
	unsigned int_64 maximum = 18446744073709551615
	increase(ref small)
	print("{small} {small:0x}") // -128 0x80
	print(maximum)            // 18446744073709551615
	int_16 wider = small
	print(wider)
```

例: [examples/types/integers.qy](../examples/types/integers.qy)。

## 新段階3の実装仕様（旧段階8、0.26.12）

新段階2から変更した点を下記にまとめる。以後はこちらを現行仕様とする。

### 型とリテラル

- `int` = `int_32`、`unsigned int` = `unsigned int_32`。別名同士は配列・ref / readonly・引数・戻り値・interfaceでも同じ型であり、int_64とは異なる。
- intの範囲は -2147483648〜2147483647、unsigned intは0〜4294967295。内部のスカラー用スロットは8バイトを維持する。
- 10進リテラルは、2147483647以下をint、2147483648〜9223372036854775807をint_64、それより大きい値をunsigned int_64とする。正の最大値は18446744073709551615。0d表記も同じ。
- 負号直後の最小値 `-2147483648` / `-0d2147483648` はint。さらに小さい値はint_64で、最小値は従来どおり `-9223372036854775808`。一般の式の型はその構成要素の型から決定する。
- 非10進リテラルも、値が2147483647以下ならint、それより大きい正の値ならint_64。従来の64bitのビット列解釈は維持するため、単独の `0xffffffff` は4294967295のint_64、`0xffffffffffffffff` は-1のint_64。先頭の0の数は推論を変えない。
- unsignedの文脈での64bitビット列の解釈と、定数が対象型に収まる場合の暗黙変換は新段階2の規則を維持する。`unsigned int mask=0xffffffff` も4294967295を表す。
- auto・型名省略の変数・定数・引数の具体化・戻り値にも上記を適用する。宣言後に変数の型は変わらない。
- intの演算とシフトは32bitで、`1 << 32` は不正。64bitの演算には `int_64(1) << 63` / `int_64(2)^63` のように**演算前の値**の型を明示する。

### 変換・入出力・サイズ

- `int(x)` / `unsigned int(x)` / `int(str,base=...)` と入力先がintのinputは32bitの範囲を検査する。int_64の値を暗黙に切り捨てない。
- `int("0xffffffff")` は32bitビット列の-1、`int_64("0xffffffff")` は4294967295。文字列読み取りは入力先のbit幅に従う。リテラルの推論とは別に、明示した変換先で解釈する。
- print・str・file.writeの基数表示は型の幅に従い、`int(-1)` は0xffffffff、`int_64(-1)` は0xffffffffffffffff。
- `.length` と `io.file.write` のバイト数はint_64を返す。配列の内部サイズ・添字、入力用ポインタ、累乗の指数、丸めの桁数も64bitを維持し、既存の大きなサイズ・指数を32bitへ切り詰めない。
- `int count=values.length` のような読み取りでは、必要なら `int(values.length)` で範囲を検査する。サイズをそのまま保持するならint_64またはautoを使用する。
- mainの戻り値型はint / int_32とする。int_64 mainは許可しない。

### forと移行

- 型を明示したforはその型を使用する。型省略時の整数カウンターは、開始値の整数型とintの安全な共通型を使用する。共通型がないunsigned int_64の開始値ではunsigned int_64を使用する。最小の既定幅は32bit。
- 例: 開始値0ではint、2147483648や `.length` ではint_64になる。終了境界は従来どおり毎周評価する。境界を調べるために値を先行実行しない。
- 終了境界だけが大きい場合、カウンターを自動で拡大しない。必要な範囲を走査するには `for(0 <= int_64 i < limit,i++);` と明示する。型の上限・下限を越える更新は従来どおりループを終了する。
- 小数カウンターは引き続きfloat / doubleを明示する。autoキーワードによるforヘッダーは導入しない。
- 64bitを前提としたテストは削除せず、int_64の宣言・演算・入力に移行する。32bitの境界と別名のref一致を別の回帰テストで検証する。
- VS Codeは宣言された別名表記を維持し、lengthとwriteの戻り値をint_64で表示する。型を省略したforはautoと表示する。拡張でコンパイラと同じ推論計算を実行するものではない。

実行例: [examples/types/default-integers.qy](../examples/types/default-integers.qy)。
回帰テスト: `make test-default-integer`（28メソッド）。

## 新段階4の実装仕様（旧段階9・10、0.26.13）

### 型・記述方法

| 型 | 実部・虚部 | 値の精度 |
| --- | --- | --- |
| complex / complex_64 | float + float | 合計64bit。complexはcomplex_64の別名 |
| complex_128 | double + double | 合計128bit |

型名のbit数は実部と虚部の合計であり、各成分は符号付き浮動小数点数とする。
128bitの浮動小数点成分やhalfは新段階5に残す。この段階のcomplex_128はdouble2個であり、quadruple2個ではない。

```text
complex z1 = complex(real=3.0, imag=4.0)
complex z2 = 3.0 + i4.0
complex z3 = 3.0 + 4.0i
```

- 推奨は前置iの `3.0 + i4.0`。後置iも同じ値を表す。i4 / 4iやi4e2 / 4e-1iにも対応する。係数は10進で、基数付きの虚数リテラルは導入しない。
- i単独は既存の識別子。iの直後が数字の名前は虚数リテラル用に予約する。`i4name` や `i4_name` は変数名として使用しない。一般の暗黙乗算は導入しない。
- 虚数リテラル単独はcomplex_128。autoや省略した引数・戻り値も同じ具体型に解決される。complexの宣言に書いたリテラル式は、既存のfloat用リテラル規則と同様にcomplex_64へ丸められる。
- complex()は0+0i、complex(3)は3+0i。real / imagは省略時0で、位置引数2個と名前付き引数を使用できる。位置引数は名前付きより前、同じ成分の重複は禁止。実行時の引数評価順は記述順であり、real / imagの順に並べ替えない。
- complex(z) / complex_128(z)は、実数または複素数からの明示変換。名前付きのreal / imagには実数を指定する。文字列からの構築はこの段階には追加しない。
- `.real` / `.imag`は読み取り専用。complex_64ではfloat、complex_128ではdoubleを返す。更新するときは複素数全体へ代入する。モデルが通常のフィールドとして宣言したreal / imagとは区別する。

### 演算・変換・所有権

- 四則演算、単項+ / -、整数の指数による^、== / !=に対応する。順序比較、%・ビット演算・boolへの暗黙変換・小数／複素数の指数は許可しない。
- 実数を虚部0へ昇格できる。complex_64とdouble変数の演算はcomplex_128へ拡大し、doubleリテラルだけの式はcomplex_64側の文脈へ合わせられる。complex_128からcomplex_64、double変数からcomplex_64への暗黙の縮小は拒否し、明示した構築・変換で丸める。
- complex_64の各演算結果は成分ごとにfloatへ丸める。中間計算にはdoubleを使用する。complex_128の中間・結果はdouble。定数評価も実行時と同じ演算順と丸めを使用する。
- 除算は分母の最大成分でスケールして計算し、通常の大きな有限値・小さな有限値で分母の二乗が先にあふれることを避ける。分母0+0iはエラー。定数なら静的に検出し、変数なら実行時エラー70。0の負の累乗も拒否し、0^0は1。
- math.abs(z) / |z|は実数の大きさ。math.sqrt(z)は主平方根で、虚部の符号に従う枝を返す。abs・sqrtは成分をスケールして演算する。round系は実数用のまま。
- 非有限値と符号付き0は浮動小数点の規則に従う。NaNを含む複素数の==はfalse、!=はtrue。有限値の範囲を越える他の演算ではinf / nanが生じ得る。
- 変数・定数・配列・モデルのフィールド・値引数・戻り値・ref / readonly・addrの指す先・ジェネリックの具体型に使用できる。配列要素と複数returnの推論は実数・複素数の共通型を使用する。
- 複素数は値として扱い、通常のコピー後の代入やref更新は元の独立したコピーへ波及しない。内部では不変の成分領域を共有し、値を変更すると新しい領域を用意する。8バイトのスカラースロットと既存GCを維持し、型名のbit数が格納領域全体のサイズを保証するものではない。
- 成分へのrefや成分へのinputは許可しない。複素数全体または配列の末端要素・モデルのフィールドへ入力する。

### 入出力・エディター

- print / file.writeは `3.0 + i4.0` / `3.0 - i4.0` の形式。成分の表示精度は既存のfloat / double表示と同じ。基数指定は整数専用のまま。
- input(z)、input("{z}")、complex z=input()に対応する。`3+i4` / `3+4i` / `i4` / `-4i` / 実部だけの3を受け付け、各成分にはe / E付きの10進指数表記も使用できる。正負の演算子の前後には空白を置けるが、iと係数は続けて書く。
- 入力は入力先の成分精度で範囲を検査する。nan / infの文字列は従来の実数入力と同じく受け付けない。失敗をboolで受け取るinputは全入力先を保持し、文として使う場合は実行時エラー65で停止する。
- 複数の入力欄にはカンマ等の区切りを推奨する。+ / - / iは複素数自体の記述にも使われる。`{z} {n}` で実部だけと負の整数を読む場合は、iがなければ別の入力欄として扱う。
- VS Codeは型名・虚数リテラルのハイライト、型付き変数と配列要素のreal / imag補完、ホバー、構築関数の引数ヒントに対応する。構築の補完は名前付きreal / imagを使用する。autoからの成分補完にはコンパイラの型推論を実行しない。

実行例: [examples/types/complex.qy](../examples/types/complex.qy)。
回帰テスト: `make test-complex`（36メソッド）。

## 後続段階で維持する設計

- auto は具体的な型に解決される。動的型・異種値を自由に格納する配列にはしない。
- 宣言済みの変数への代入は、その型を維持する。未宣言名の複合代入・インクリメントはエラー。
- 汎用関数は静的に具体化する。戻り値が int であることから、引数型まで int に固定しない。
- 推論が循環する再帰では、必要な型注釈を要求する。具体化の無制限な展開も診断する。
- 整数型の桁数は型全体のbit数。暗黙変換で負数を巨大なunsignedに変えたり、上位bitを捨てたりしない。
- complex のbit数も型全体。実部・虚部は符号付き浮動小数点であり、unsigned整数にはしない。
- `i` 単独は識別子として維持し、`i4` 等は虚数リテラルとして予約する。暗黙の一般的な乗算は導入しない。
- 数値リテラルは、対象型が決まった精度で直接変換する。広い型のリテラルを先に double に丸めない。
- bool の正式表記は true / false。char / str の正規化は明示操作とする。
- 各段階の時点で未導入の型・構文はエラーにし、将来仕様を実装済みとして案内しない。
