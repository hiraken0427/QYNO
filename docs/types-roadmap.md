# 型の整備と推論の段階的な実装

## 運用

ユーザーが承認した型設計を、下記の順で実装する。各段階は検証可能な変更として
dev にコミットし、hiraken0427 名義で **1 回 push したら次の指示を待つ**。
複数段階をまとめて実装・push しない。main への反映は通常の dev → main PR を使う。
バージョン番号は各実装時に確定する。第1段階は 0.26.6、第2段階は 0.26.7、第3段階は 0.26.8。

各段階で必要な個別テストを行った後、最終の `make test` を1回だけ実行する。
ZIP 展開後の再ビルド・再テストはしない。
新しい値型は、その段階で配列・ref・定数評価・入出力・Linux/Windows 出力にも対応させる。

## 実装順

| 段階 | 内容 | その段階の到達点 |
| --- | --- | --- |
| 1 | ローカル変数の明示的な auto（0.26.6、実装済み） | `auto n = 3`、`const auto N = 3`。既存の具体的な値型を初期値から推論する |
| 2 | 型名を省略したローカル宣言とスコープ（0.26.7、実装済み） | 未宣言の `y = 3` を宣言にする。既存変数への代入、明示的な内側スコープの同名宣言、未使用変数の警告に対応する |
| 3 | ファイル先頭の const の型推論（0.26.8、実装済み） | `const auto LIMIT = 3` と `const LIMIT = 3`。モジュール間参照・前方参照・循環診断に対応する |
| 4 | 型を指定した引数からの戻り値推論 | `auto f(int x) = x^2` と `f(int x) = x^2`。複数 return と再帰の扱いを実装する |
| 5 | 型を省略した関数引数 | `f(x) = x^2` を引数型ごとに具体化する。`int f(x)` は戻り値 int の制約を維持する |

| 7 | 64bit 以下の符号無し整数型 | `unsigned int_8` / `unsigned int_16` / `unsigned int_32` / `unsigned int_64`。混在時の安全な変換・ゼロ埋め右シフトを用意する |
| 8 | int の32bit化と数値リテラル推論 | int / unsigned int を32bitの別名へ移行する。リテラルの文脈・範囲による型選択と既存コードの移行を一緒に検証する |
| 9 | 複素数の型と構築関数 | complex = complex_64（float + float）、complex_128（double + double）。`complex(real=3.0, imag=4.0)`、演算・実部虚部・入出力を実装する |
| 10 | 虚数リテラル | `3.0 + i4.0` と `3.0 + 4.0i`。推奨は前置 i。文脈に応じた精度と既存識別子との衝突診断を整備する |
| 11 | 128bit 整数 | int_128 / unsigned int_128。2ワード演算・除算・変換・入出力・呼出規約に対応する |
| 12 | 半精度浮動小数点 | half（binary16）。格納・丸め・演算・変換・入出力を規定どおり実装する |
| 13 | 四倍精度浮動小数点 | quadruple（binary128）。既存の double を経由せず、リテラルと演算の精度を保証する |
| 14 | 書記素クラスタの char / str | Unicode バージョンと拡張書記素クラスタ規則を固定する。length・添字・入力・置換を一括して移行する |
| 15 | 値型としての void | 唯一の値 `()`、void の変数・配列・引数・戻り値を統一し、0サイズ要素の ref / addr も定義する |

既存機能を使う型推論から着手し、関数の具体化は小さく分ける。
整数の幅を追加する段階と、既定の int の意味を変える段階も分離する。
128bit 演算・Unicode・0サイズ値は処理系の広い変更を伴うため後半に置く。

## auto の共通仕様（第1段階から）

関数・メソッド・init の本体で、初期値付きのローカル宣言に使用できる。

```text
int main();
	auto count = 3
	auto ratio = 0.5
	auto title = "QYNO"
	auto enabled = true
	auto values = [[1, 2], [3, 4]]
	const auto LIMIT = 10
	print("{count} {ratio} {title} {enabled} {values} {LIMIT}")
	return 0
```

- auto は実行時の型ではなく、初期値の型を宣言に採用する指定。代入後に型は変わらない。
- int はこの段階では従来の64bit、char はUnicodeスカラー値1個のまま。
- 小数リテラルは double、文字列リテラルは str。float / char は変換関数や既存の型付き値から推論できる。
- 配列は既存の要素型・次元数の推論を使用する。`auto values = [1, 2]` と書き、名前の後に次元は指定しない。推論した配列に固定上限は付かない。
- 空配列や `{x=1}` のように型の文脈が必要な初期化子だけでは推論できない。モデルは型付き変数や戻り値から推論する。
- 配列・モデルは既存の独立したコピー、file は既存の共有ハンドルとして扱う。readonly と明示 close の検査も維持する。
- `input()` の戻り値をそのまま推論すると str。`input(target)` は bool。入力先の型を後から実行時に推測しない。
- 初期値を省略できない。自己参照と同じスコープの重複宣言は禁止する。第2段階からは、明示的な内側の宣言で外側のローカル変数を隠すことができる。
- 第3段階からはファイル先頭の const にも対応する。フィールド、引数、戻り値、ref 宣言、for ヘッダーには auto を導入しない。
- addr / none、戻り値のない式、interface の所有値を推論して格納することはできない。
- auto は予約語になる。従来 auto を識別子にしていたコードは名前の変更が必要。

VS Code は auto のハイライト、名前補完・定義参照に対応する。
拡張はコンパイラとは独立した構文解析を使うため、ホバーには宣言どおり auto を表示し、
この段階では推論された型に基づくメンバー補完は行わない。

## 第2段階の実装仕様（0.26.7）

未宣言の単純な名前への `=` は、現在のブロックに変数を宣言する。
初期値は auto と同じ規則で推論し、配列・モデル・file の扱いも同じ。

```text
int main();
	count = 3
	if(true);
		count = count + 1       // 外側の変数へ代入
		auto count = str(count) // 初期値では外側を参照し、別の変数を宣言
		print(count + "!")
	print(count)               // 外側の int、値は4
	return 0
```

- 既存のローカル変数・引数への `=` は代入。内側のブロックでも同じ参照先と型を維持する。
- 同名の別変数を作る場合は、内側で型または auto を明示する。const / ref の明示宣言でも同じスコープ規則を使う。
- 初期値は、新しい変数を登録する前のスコープで解釈する。外側に同名の変数があれば初期値から参照できる。
- 同じブロックでの二重宣言、および関数・メソッド本体直下での引数と同名の宣言はエラー。
- this はモデルの暗黙引数として維持し、内側の宣言でも隠せない。
- 分岐・ループ内の新規変数は、そのブロック内だけで有効。兄弟ブロックに同じ名前の別変数を宣言できる。
- `+=` / `-=` / `++` / `--`、添字・フィールド・value・addr への更新は新規宣言にならない。元の変数が必要。
- 定数、関数、型、import / using の名前を型名省略の宣言で置き換えることはできない。明示的な宣言のモジュール名衝突規則も維持する。
- ファイル先頭の代入は未対応。`const NAME = ...`・ファイル先頭の `const auto NAME = ...` は第3段階で追加する。
- for ヘッダーは従来どおり専用のループ変数を宣言する。外側と同名にする場合は `for(0 <= int i < 3, i++);` のように型を明示する。
- ref の寿命検査・readonly・interface の所有制限・file の明示 close の検査は、名前や宣言方法を変えても維持する。

警告は、今回導入した **型名を省略した宣言** が読み取り・参照されない場合に出す。
単純な再代入だけでは使用とみなさない。複合更新、入力先、ref 引数、addr 参照、埋め込み文字列中の参照は使用とみなす。
明示的な型付き宣言・auto・const の既存の警告動作は変更しない。
警告はソース位置を示すが、コンパイルは成功し、初期値の副作用も実行する。
警告は制御フロー上の実行可能性を判定するものではない。

未使用の名前と、宣言位置で見えていたローカル変数・引数の名前が1文字の挿入・削除・置換・隣接入れ替えで一致する場合、候補を示す。
誤候補を減らすため双方3文字以上とし、変数名を自動修正しない。interface の具体化でも元の宣言ごとに1回だけ警告する。

VS Code は型名を省略したローカルの宣言・代入を区別し、ブロックと宣言位置に従って名前補完・定義参照を行う。
推論した具体型の表示は引き続き行わず、宣言の型を auto と表示する。

## 第3段階の実装仕様（0.26.8）

型推論付き定数を、ファイル先頭にも宣言できる。`const NAME = 初期値` は `const auto NAME = 初期値` と同じ意味で、ローカルにも使える。

```text
const LIMIT = BASE + 1
const auto BASE = 3
const LABEL = "QYNO"

int main();
	int values[LIMIT]
	print("{LABEL}: {values.length}")
	return 0
```

- 型は初期値から決め、値はコンパイル時に計算する。通常の関数・メソッド・input・ファイル操作を定数式として実行することはない。
- ファイル先頭の定数は、宣言より前の関数・定数から参照できる。型を明示した従来の定数と混在できる。
- import、名前空間の修飾名、using、モジュール別名を通して型と値を解決する。名前は各モジュールのスコープに属する。
- 型推論に必要な定数を先に検査・評価し、結果を再利用する。推論または評価が同じ定数へ戻る循環はエラー。
- 未解決の定数を同時に調べる深さは256段までとし、深すぎる場合はコンパイルエラーにする。
- 配列は初期値から要素型・次元数を推論する。空配列だけでは型を決められないが、型を明示した空配列の定数からの推論は可能。
- モデルは型付きの定数や `Point()` のような構築式から推論できる。`{x=3}` だけではモデルの型を決められない。
- init を含むモデルの定数化、file を含むモデルの定数化、private / readonly / interface の制約は維持する。
- 配列上限、モデルのフィールド既定値、init の既定引数でも推論付き定数を使用できる。モデル既定値も依存する定数に合わせて必要な順で検査する。
- 定数自体とその要素・フィールドへの代入、変更可能な ref 渡し、addr の取得は禁止。通常の値渡し・ローカルへの独立したコピー・readonly の借用は可能。
- ファイル先頭の変更可能な変数、関数の引数・戻り値の推論は導入しない。
- ファイル先頭の定数とローカルの const は、第2段階の未使用変数警告の対象にしない。

VS Code は両方の定数宣言を認識し、前方参照・モジュール経由の補完・定義参照・ホバー・アウトラインに対応する。
型表示は `const auto NAME` とし、この段階でもコンパイラの推論結果を表示するものではない。

## 後続段階で維持する設計

- auto は具体的な型に解決される。動的型・異種値を自由に格納する配列にはしない。
- 宣言済みの変数への代入は、その型を維持する。未宣言名の複合代入・インクリメントはエラー。
- 汎用関数は静的に具体化する。戻り値が int であることから、引数型まで int に固定しない。
- 推論が循環する再帰では、必要な型注釈を要求する。具体化の無制限な展開も診断する。
- 整数型の桁数は型全体のbit数。暗黙変換で負数を巨大なunsignedに変えたり、上位bitを捨てたりしない。
- complex のbit数も型全体。実部・虚部は符号付き浮動小数点であり、unsigned整数にはしない。
- `i` 単独は識別子として維持し、`i4` 等は虚数リテラルとして予約する。暗黙の一般的な乗算は導入しない。
- 数値リテラルは、対象型が決まった精度で直接変換する。広い型のリテラルを先に double に丸めない。
- bool の正式表記は true / false。char / str の正規化は明示操作とする。
- 各段階の時点で未導入の型・構文はエラーにし、将来仕様を実装済みとして案内しない。
