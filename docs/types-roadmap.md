# 型の整備と推論の段階的な実装

## 運用

ユーザーが承認した型設計を、下記の順で実装する。各段階は検証可能な変更として
dev にコミットし、hiraken0427 名義で **1 回 push したら次の指示を待つ**。
複数段階をまとめて実装・push しない。main への反映は通常の dev → main PR を使う。
バージョン番号は各実装時に確定する。第1段階は 0.26.6。

各段階で必要な個別テストを行った後、最終の `make test` を1回だけ実行する。
ZIP 展開後の再ビルド・再テストはしない。
新しい値型は、その段階で配列・ref・定数評価・入出力・Linux/Windows 出力にも対応させる。

## 実装順

| 段階 | 内容 | その段階の到達点 |
| --- | --- | --- |
| 1 | ローカル変数の明示的な auto（0.26.6、実装済み） | `auto n = 3`、`const auto N = 3`。既存の具体的な値型を初期値から推論する |
| 2 | 型名を省略したローカル宣言とスコープ | 未宣言の `y = 3` を宣言にする。既存変数への代入、明示的な内側スコープの同名宣言、未使用変数の警告を整備する |
| 3 | ファイル先頭の const の型推論 | `const auto LIMIT = 3` と `const LIMIT = 3`。モジュール間参照・前方参照・循環診断を維持する |
| 4 | 型を指定した引数からの戻り値推論 | `auto f(int x) = x^2` と `f(int x) = x^2`。複数 return と再帰の扱いを実装する |
| 5 | 型を省略した関数引数 | `f(x) = x^2` を引数型ごとに具体化する。`int f(x)` は戻り値 int の制約を維持する |
| 6 | 64bit 以下の符号付き整数型 | `int_8` / `int_16` / `int_32` / `int_64`。この時点の int は互換性のため64bitのまま。幅別の範囲検査・演算・配列・変換を用意する |
| 7 | 64bit 以下の符号無し整数型 | `unsigned int_8` / `unsigned int_16` / `unsigned int_32` / `unsigned int_64`。混在時の安全な変換・ゼロ埋め右シフトを用意する |
| 8 | int の32bit化と数値リテラル推論 | int / unsigned int を32bitの別名へ移行する。リテラルの文脈・範囲による型選択と既存コードの移行を一緒に検証する |
| 9 | 複素数の型と構築関数 | complex = complex_64（float + float）、complex_128（double + double）。`complex(real=3.0, imag=4.0)`、演算・実部虚部・入出力を実装する |
| 10 | 虚数リテラル | `3.0 + i4.0` と `3.0 + 4.0i`。推奨は前置 i。文脈に応じた精度と既存識別子との衝突診断を整備する |
| 11 | 128bit 整数 | int_128 / unsigned int_128。2ワード演算・除算・変換・入出力・呼出規約に対応する |
| 12 | 半精度浮動小数点 | half（binary16）。格納・丸め・演算・変換・入出力を規定どおり実装する |
| 13 | 四倍精度浮動小数点 | quadruple（binary128）。既存の double を経由せず、リテラルと演算の精度を保証する |
| 14 | 書記素クラスタの char / str | Unicode バージョンと拡張書記素クラスタ規則を固定する。length・添字・入力・置換を一括して移行する |
| 15 | 値型としての void | 唯一の値 `()`、void の変数・配列・引数・戻り値を統一し、0サイズ要素の ref / addr も定義する |

既存機能を使う型推論から着手し、関数の具体化は小さく分ける。
整数の幅を追加する段階と、既定の int の意味を変える段階も分離する。
128bit 演算・Unicode・0サイズ値は処理系の広い変更を伴うため後半に置く。

## 第1段階の実装仕様

関数・メソッド・init の本体で、初期値付きのローカル宣言に使用できる。

```text
int main();
	auto count = 3
	auto ratio = 0.5
	auto title = "QYNO"
	auto enabled = true
	auto values = [[1, 2], [3, 4]]
	const auto LIMIT = 10
	print("{count} {ratio} {title} {enabled} {values} {LIMIT}")
	return 0
```

- auto は実行時の型ではなく、初期値の型を宣言に採用する指定。代入後に型は変わらない。
- int はこの段階では従来の64bit、char はUnicodeスカラー値1個のまま。
- 小数リテラルは double、文字列リテラルは str。float / char は変換関数や既存の型付き値から推論できる。
- 配列は既存の要素型・次元数の推論を使用する。`auto values = [1, 2]` と書き、名前の後に次元は指定しない。推論した配列に固定上限は付かない。
- 空配列や `{x=1}` のように型の文脈が必要な初期化子だけでは推論できない。モデルは型付き変数や戻り値から推論する。
- 配列・モデルは既存の独立したコピー、file は既存の共有ハンドルとして扱う。readonly と明示 close の検査も維持する。
- `input()` の戻り値をそのまま推論すると str。`input(target)` は bool。入力先の型を後から実行時に推測しない。
- 初期値を省略できない。自己参照・重複宣言・外側の変数を隠す宣言は、既存仕様どおり禁止する。
- この段階では、型名を省略した代入、ファイル先頭の const、フィールド、引数、戻り値、ref 宣言、for ヘッダーには auto を導入しない。
- addr / none、戻り値のない式、interface の所有値を推論して格納することはできない。
- auto は予約語になる。従来 auto を識別子にしていたコードは名前の変更が必要。

VS Code は auto のハイライト、名前補完・定義参照に対応する。
拡張はコンパイラとは独立した構文解析を使うため、ホバーには宣言どおり auto を表示し、
この段階では推論された型に基づくメンバー補完は行わない。

## 後続段階で維持する設計

- auto は具体的な型に解決される。動的型・異種値を自由に格納する配列にはしない。
- 宣言済みの変数への代入は、その型を維持する。未宣言名の複合代入・インクリメントはエラー。
- 汎用関数は静的に具体化する。戻り値が int であることから、引数型まで int に固定しない。
- 推論が循環する再帰では、必要な型注釈を要求する。具体化の無制限な展開も診断する。
- 整数型の桁数は型全体のbit数。暗黙変換で負数を巨大なunsignedに変えたり、上位bitを捨てたりしない。
- complex のbit数も型全体。実部・虚部は符号付き浮動小数点であり、unsigned整数にはしない。
- `i` 単独は識別子として維持し、`i4` 等は虚数リテラルとして予約する。暗黙の一般的な乗算は導入しない。
- 数値リテラルは、対象型が決まった精度で直接変換する。広い型のリテラルを先に double に丸めない。
- bool の正式表記は true / false。char / str の正規化は明示操作とする。
- 各段階の時点で未導入の型・構文はエラーにし、将来仕様を実装済みとして案内しない。
